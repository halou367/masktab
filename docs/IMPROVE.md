## I-1 内核外置：安装包 = 更新包（需求方 2026-11-14）

### 为什么

- 手机安装包 127.6 MB（arm64），其中 GeckoView 约 85 MB（`libxul.so` 70.7 MB + `omni.ja` 14.7 MB），mihomo 24 MB，MaskTab 自己不到 20 MB。每次更新都要重新下这 127 MB。
- 电脑有两个安装包：普通包（几 MB，不带内核）和完整包（带 Chromium 约 190 MB、mihomo 约 22 MB）。两个包容易拿错。

### 做成什么样

1. 每个平台只有一个安装包，不带内核，安装和更新都用它。
2. 第一次启动自动下载内核并加载；以后只有内核版本变了才重新下。
3. 下载依次试：直连 → 本机代理（7890、18080，以及设置里填的端口）→ 镜像。断点续传，下载完校验 SHA-256，对不上就丢弃。
4. 全都不通时明确提示：“请打开代理软件（端口 7890 或 18080）后点重试”，同时给“换镜像”“改端口”“从文件导入”三个出口。
5. 设置里新增“组件与更新”：内核版本、检查更新、重新下载、从文件导入、下载途径、镜像前缀、本机代理端口。
6. 两端的下载页面是同一个页面（见演示页“首次启动 · 下载内核”）。

### 电脑：改动小，路是通的

已有的：普通包、下载链路（直连 → 本机代理 → 镜像，D-1）、断点续传、SHA-256 校验、进度页、镜像前缀设置；`internal/netx` 的探测端口里已经有 7890 和 18080。

要做的：

- CI 和安装脚本去掉完整包（`MaskTab-Setup-Full.exe`、`-DFULL`），只发 `MaskTab-Setup.exe`。
- 下载失败的提示改成上面第 4 条的样子（现在只说“手动放文件后重试”）。
- 设置里加“本机代理端口”（默认 `7890, 18080`，排在自动探测的其它端口前面）和“下载途径”。
- “从文件导入”：选一个已经下好的内核包，校验后解压。
- 进度页换成和手机同一份界面。

### 手机：有技术风险，先验证再承诺

GeckoView 不是为“内核放在安装包外面”设计的。已经确认的事实（读 GeckoView 160 源码和安装包）：

- 它用 `System.loadLibrary` 从安装包自己的库目录加载 `libxul.so`；`omni.ja` 从安装包本身读取（启动参数 `-greomni <安装包路径>`）。
- 内容进程、GPU 进程等是清单里声明的 90 个服务，由系统按安装包里的类来启动。
- mihomo 现在是当作可执行文件从安装包的库目录里运行的；安卓 10 起不允许执行数据目录里的文件，所以它不能简单地“下载下来再运行”。

候选路线（**都还没有做过原型，下面的体积是估算**）：

| 路线 | 做法 | 安装包估算 | 好处 | 风险 |
|---|---|---|---|---|
| A 拆分安装包 | 用系统自带的“拆分 APK”机制：主包只有 MaskTab 自己 + `omni.ja`；内核库和 mihomo 做成一个“内核分包”，首次启动时下载，再由系统安装进来 | 约 25～30 MB | 不改 GeckoView 的加载方式，子进程、mihomo 都照常工作 | 装内核分包时系统会弹一次“是否更新此应用”；vivo 等厂商系统对拆分安装的支持要在真机上试；主包和分包的版本号必须一致，更新主包时要用固定的内部版本号 |
| B 自己加载 | 内核整包（类、库、`omni.ja`）下载到应用私有目录，用单独的类加载器加载 | 约 20～45 MB（mihomo 能不能一起外置要另验） | 没有系统弹窗 | 要接管系统启动子进程的过程（安卓 9 / 10 以上才有这个接口，最低系统版本要从 8 提到 10）；`omni.ja` 路径要绕；GeckoView 每次升级都可能要重新适配 |
| C 做不到时的退路 | 内核仍然在安装包里，只把 MaskTab 自己的界面和逻辑（内置扩展）做成可以单独在线更新 | 首次仍是约 128 MB，之后的更新不到 1 MB | 一定能做 | 不满足“安装包小”，只解决“更新包大” |

顺序：

1. 先做路线 A 的验证版：只验证“小主包装得上 → 下载分包 → 系统安装 → 内核起得来 → 更新主包后内核还在”。CI 模拟器跑通后发给需求方在真机上试。
2. A 在真机上不行，再试 B。
3. A、B 都不行，按 C 做，并如实告知。

验证通过之前，不对手机安装包的最终大小做承诺。模拟器跑通不等于真机没问题（0.1.9 的教训）。

### 没验证的

- 手机三条路线全部没有原型。
- 手机内核分包放在哪里：本仓库是私有的，应用没法从这里的 Release 下载。需要一个公开的下载位置（比如单独建一个只放内核包的公开仓库，这样 GitHub 镜像也能用），**待需求方决定**。电脑的 Chromium 内核和 mihomo 本来就是从公开的发布页下载，不受影响。
- 镜像站对内核包这种 100 MB 左右的大文件是否稳定。
- 国内网络下各条下载途径的实际表现。

## I-2 两端界面统一（需求方 2026-11-14）

### 为什么

手机 0.1.13 的“节点与出口”“指纹与时区”是另写的简化页面，和电脑不是一个样子，功能也少：
只有一个订阅地址输入框，没有出口（ProxyIP）列表、入口（优选 IP）列表、地址库，看不到两路出口、类型和纯净度。

### 做成什么样（见演示页）

原则：**一份界面，两端共用**。电脑上是工具栏弹出的面板 / 标签页里的管理页，手机上是整页；同一份代码按宽度自己变形，不再各写一套。

| 页面 | 电脑 | 手机 | 这次的变化 |
|---|---|---|---|
| 首次启动 · 下载内核 | 启动窗口 | 整页 | 新增（I-1） |
| 实例菜单 | 点头像弹出 | 点头像整页 | 手机菜单项和电脑对齐 |
| 节点与出口 | 工具栏按钮弹出 | 整页 | 手机换成和电脑同一个面板：两路出口、类型、纯净度、订阅切换、出口 / 入口各自的自动开关 |
| 指纹与时区 | 面板里展开 | 面板里展开 | 字段两端相同；手机上“系统”“浏览器”固定（UA 必须和内核一致），标出来 |
| 出口国家 / 出口列表 / 入口列表 | 面板内换页 | 整页 | 手机新增 |
| 管理 · 实例 | 标签页，左侧图标栏 | 整页，底部标签栏 | 同一页 |
| 管理 · 订阅与地址库 | 同上 | 同上 | 手机新增：订阅管理 + ProxyIP / 优选 IP / 其它代理的地址库，批量导入 |
| 管理 · 扩展 | 同上 | 同上 | 页面相同；扩展来源不同（Chrome 商店 / Firefox 商店） |
| 管理 · 设置 | 同上 | 同上 | 设置项对齐、同样分组；新增“组件与更新” |
| 诊断信息 | 弹窗 | 弹窗 | 电脑补上 |

### 手机更精简（需求方 2026-11-14 追加：“双端尽可能统一，手机端甚至要更精简”）

组件、图标、颜色、顺序和电脑相同，手机上每一块少一层。演示页右上角可以在“手机精简 / 手机与电脑相同”之间切换对比。规则：

- 一行一件事。节点面板里订阅、出口、入口各一行；两路出口各一行，相同时只显示一行；底部按钮去掉（菜单里有）。
- 次要信息收起来，点一下才展开：订阅和地址的操作、扩展的范围和数据模式、指纹里的“更多”、设置里的“高级”。
- 输入框平时不显示，点“+”才出现。
- 类型（住宅 / 机房、优选 / 反代）用图标表示；排序是一个按钮，点一下换一种。
- 手机上没有悬停提示，所以图标旁保留两个字的标签（订阅、出口、入口、自动）。
- 设置里的“高级”一组两端都有：电脑默认展开，手机默认收起。
- 首次启动只显示当前这一步和一根进度条；出问题时的提示和按钮与电脑相同。

待定：电脑的节点面板宽 320 px，和手机差不多宽，可以直接用手机这套精简布局，两端就完全一样（演示页右上角“电脑面板同手机”可以看效果）。等需求方选。

### 怎么做

- 界面：电脑的 `popup.js` / `app.js` 和手机的 `main.js` 合成一套共用页面，放在共用目录里；只有“怎么和后台说话”分两份（电脑走核心服务的 HTTP 接口，手机走 `Bridge`）。
- 手机后台要补的能力（现在没有，界面只是壳的话没意义）：
  - 多个订阅、订阅类型识别（edgetunnel / 通用）；
  - edgetunnel 订阅的出口（ProxyIP）和入口（优选 IP）分开选、自动 / 手动、按国家自动挑、不通自动换；
  - 地址库：导入、域名展开、本机直接探测延迟、测下载；
  - 两路出口探测、类型和纯净度查询。
  电脑上这些在 Go 的核心服务里（`internal/proxy`、`internal/exits`、`internal/subscription`、`internal/core/scan.go`）。手机上要么用 Kotlin 重写一遍，要么把这部分 Go 代码编成库给手机用——后者能保证两端行为一致，倾向后者，落地前先验证能不能编、体积多大。
- 手机上不使用“圆角 + 可滚动”的容器（0.1.13 的教训，A-8）：演示页里电脑弹出面板是圆角可滚动的，手机上同一个面板是整页，由页面本身滚动。

### 分期

1. 第一期（界面统一，后台已有的功能）：实例菜单、节点与出口面板、指纹与时区、管理页四个标签、设置对齐、诊断。手机上后台还没有的功能先不显示入口，不放假按钮。
2. 第二期（手机补后台）：多订阅、出口 / 入口列表、地址库、两路出口与纯净度。
3. 每期：电脑走 CI 冒烟，手机走 CI 模拟器，再请需求方在真机上确认。

### 没验证的

- 把 Go 的选线 / 探测代码编给安卓用是否可行、体积多少。
- 共用页面在 GeckoView 上的表现（演示页只在桌面 Chromium 里看过）。
