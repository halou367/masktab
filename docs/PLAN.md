## 1. 产品定义

### 1.1 一句话

一个轻量的多实例浏览器：平时打开就是普通的 Chromium 窗口；按 `Ctrl+M` 新开一个带颜色的"伪装实例"窗口，它有自己独立的登录状态、指纹、代理出口和时区，和其他窗口互不相通；扩展、密码、设置默认全局统一。

### 1.2 设计原则（发生冲突时按此顺序取舍）

1. **不串**：实例之间、实例与普通窗口之间，数据和网络出口绝不相通。
2. **不漏**：实例的任何流量都不得绕过它的代理端口；代理坏了就断网，不回落直连。
3. **自洽**：时区、语言必须和出口 IP 一致；**一旦不一致立即断流**，直到修正。
4. **全局为主**：除了和 IP、指纹相关的，其余（扩展、密码、书签、设置）默认全局统一。
5. **图标优先**：我们自己画的界面尽量不放文字，鼠标悬停才出文字提示。
6. **做减法**：浏览器本体功能全部用内核原生的，不重复造；不在清单里的功能不做。

### 1.3 非目标（明确不做）

- 自绘浏览器外壳、同窗口混排不同实例的标签（窗口底栏在 P0、P1 不做，后续增强见 F-COMP-2）
- 规则分流、TUN、系统代理（只做"每实例全局走一个节点"）
- 修改 Chromium 源码（只用现成内核的命令行开关）
- 内置广告拦截、翻译、AI 助手（需要就装扩展）
- 账号体系、官方云服务（同步用用户自己的 Worker 或 WebDAV）
- 自动化接口、批量操作、团队协作
- iOS

### 1.4 资源预算（M8 验收用）

| 指标 | 目标 |
|---|---|
| 安装包 | ≤ 170 MB（内核约占 130 MB） |
| 核心服务常驻内存 | ≤ 40 MB |
| 代理内核内存（20 个活跃实例） | ≤ 80 MB |
| 从按下 `Ctrl+M` 到新窗口可用 | ≤ 3 秒（含出口探测） |
| 休眠实例（窗口已关） | 0 开销 |
| 每个打开的实例 | 一个完整浏览器进程组，约 200–300 MB 起（估算值，M0 实测后写入决策记录） |

## 3. 关键决策

### 3.1 决策总表

| 编号 | 问题 | 结论 | 理由 |
|---|---|---|---|
| D1 | 产品形态 | 真实 Chromium 内核；**每个实例 = 一个独立进程 + 独立用户数据目录 + 独立窗口** | 进程级隔离最彻底；代理、时区、指纹在启动参数里就定死，从第一个请求起就不会漏；扩展和 Google 登录都是原生行为。 |
| D2 | 用哪个内核 | 内核可插拔。默认 **fingerprint-chromium**（基于 Ungoogled Chromium 的开源指纹内核）；备选普通 Ungoogled Chromium | 默认内核用命令行开关就能在引擎层设置指纹种子、时区、语言、CPU 核数、WebRTC 策略，不需要我们改源码。不能用官方品牌 Chrome：它从 137 版起不再支持命令行加载扩展。 |
| D3 | 管理程序 | **Go 写的单文件核心服务** + 托盘图标 | 体积约 10 MB、无运行时依赖；Android 端可复用同一份 Go 逻辑。 |
| D4 | 自绘界面放哪 | **伴随扩展**：工具栏按钮（国旗 + 延迟）、弹出面板、扩展内页面、新标签页 | 不改内核就能拥有的全部界面位置。 |
| D5 | 代理内核 | mihomo 单进程，每个活跃实例一个本地入站端口，入站直接绑定该实例的策略组 | 和 FlClash 同内核；天然"无规则、全局"；自带测速和流量接口。 |
| D6 | 代理开关怎么做 | 浏览器始终指向本地端口；开 / 关 / 断流 = 在 mihomo 里把该实例的策略组切到 节点 / DIRECT / REJECT | 切换不需要重启浏览器；默认项是 REJECT，任何异常都落在"断流"而不是"直连"。 |
| D7 | 要不要兼容非 edgetunnel 订阅 | **要兼容** | 见 3.3。 |
| D8 | 出口 IP 怎么认定 | 以实测为准，分两条路径探测；优选 IP 提供"同出口"模式 | 见 3.2。 |
| D9 | 扩展 | 全局扩展库；每个扩展两个开关：范围（全部实例 / 指定实例）、数据（独立 / 共享） | 见 5.5。 |
| D10 | 油猴 | 直接把油猴扩展装进全局库并设为"共享"数据模式 | 脚本只需维护一份。 |
| D11 | 密码管理 | 伴随扩展负责识别与填充，核心服务保管全局保险库，每条记录带实例编号 | 符合"全局记录、按 #1 #2 管理"；内核自带的密码管理按实例隔离，不满足需求，予以关闭。 |
| D12 | 哪些改动需要重启实例 | 时区、语言、指纹、扩展集合变更需要重启该实例（一键完成，标签自动恢复）；代理开关、换节点、换优选 IP、换出口不需要 | 前者是进程启动参数。 |
| D13 | 同步 | 自建 Cloudflare Worker（KV）或 WebDAV 存一份端到端加密快照；手动上传、提示更新、合并上传 | 两端不需要同时在线；请求量极小。 |
| D14 | 移动端 | 只做 Android；系统 WebView + 多进程槽位 | 见第 9 章。 |

### 3.2 必读：edgetunnel 的出口 IP 由谁决定

edgetunnel 的转发顺序是：先从 Cloudflare 边缘直接连目标；连不上（目标本身托管在 Cloudflare 上）才改走 ProxyIP；如果 path 指定了全局 SOCKS5/HTTP，则全部走它。因此：

| 访问的网站 | 网站看到的 IP | 由什么决定 |
|---|---|---|
| 托管在 Cloudflare 上的网站 | ProxyIP 那台机器的出口 | 出口条目（proxyip） |
| 不在 Cloudflare 上的网站（Google / Gmail、微软、亚马逊等） | Cloudflare 边缘机房的出口 IP（一个共享池，可能在几个 IP 间变化） | 优选 IP 落到哪个机房 |
| path 里用全局 `socks5://` 或 `http://` | 该代理的 IP | 出口条目（socks5 / http） |

对本项目的影响：

1. **只换 proxyip，Gmail 看到的 IP 不会变**。要让 Gmail 侧的出口国家不同，得换优选 IP（换机房），或使用 socks5 / http 类型的出口条目，或使用非 edgetunnel 节点。
2. 每个实例必须探测**两个出口**：CF 路径出口和直连路径出口（算法见 8.5）。两者国家不一致时，工具栏按钮显示警示。
3. 时区默认跟随 proxyip 出口（按原稿要求），但允许每实例改为跟随直连路径出口（主要用 Google 的实例应选这个）。

【需验证 V5】用真实订阅复现上表。

**让两路出口一致的办法："优选 IP 同出口"**

如果一个 proxyip 本身能当入口用（它就是一台把 443 端口反代到 Cloudflare 的机器），把节点的 address 也填成它：客户端经这台机器进入 Cloudflare，落到离它最近的机房，于是

- 托管在 Cloudflare 上的网站看到：proxyip 的出口；
- 其他网站（Gmail 等）看到：该机房的 Cloudflare 出口 IP，**通常与 proxyip 同一国家**。

两路国家一致，时区也就自洽。代价是速度和延迟一般。注意两点：其他网站看到的仍是 Cloudflare 的 IP 而不是 proxyip 本身；落到哪个机房由那台机器的网络路由决定，一般同国但不保证，所以双路探测和不一致警示仍然保留。规格见 F-PROXY-25。

### 3.3 回答原稿的问题：非 edgetunnel 节点会不会"一个窗口一个代理"导致内存爆

不会。

- 代理内核（mihomo）只有**一个进程**。每个实例在它里面只是"一个本地监听端口 + 一条出站配置"，单条开销是 KB 到几百 KB 级别，真正占内存的是活跃连接。
- edgetunnel 也一样：每个实例的 path 不同，对代理内核来说就是一条独立出站。**两种订阅的资源模型完全相同**，只支持 edgetunnel 并不会更省。
- 所以结论是：edgetunnel 作为一等公民（拆分选择优选 IP / Host / 出口），其他订阅走通用模式（整节点选择），共用同一套代理内核和界面。

### 3.4 本路线的已知代价（需求方须知情）

| 代价 | 说明 | 对策 |
|---|---|---|
| 没有窗口底栏 | 代理信息改在工具栏按钮上：图标是国旗，角标是延迟，悬停出详情，点击出节点面板 | 把伴随扩展按钮固定在工具栏最显眼处 |
| 内存 | 每个打开的实例是一个完整的浏览器进程组 | 窗口关闭即休眠，零开销；只开正在用的 |
| 部分改动要重启实例 | 时区、语言、指纹、扩展集合 | 一键重启，标签自动恢复 |
| 默认内核是第三方构建 | fingerprint-chromium 由个人维护；账号都在它里面登录 | 只从其官方发布页下载并校验哈希；内核可插拔，随时可换成 Ungoogled Chromium 或自行编译 |
| 共享模式的扩展数据不是实时互通 | 在实例启动和退出时同步，见 5.5 | 提供"立即同步"按钮；实时互通列为 P2 |

### 3.5 退路

- 默认内核停更或出问题 → 切换到 Ungoogled Chromium，指纹改由伴随扩展在页面主世界注入（强度下降为"中"），时区改用环境变量或调试接口。因此**所有与内核相关的代码必须收在 `KernelAdapter` 接口后面**。
- 将来一定要同窗口混排标签或窗口底栏 → 只能自绘外壳或改 Chromium 源码，属于另一个项目。

## 4. 总体架构

```
              ┌──────────────── 核心服务（Go，单文件，托盘常驻）────────────────┐
              │ InstanceManager   KernelAdapter   ProfilePreparer              │
              │ ProxyManager ─ CoreManager(mihomo 子进程) ─ ConfigGen           │
              │ Subscription   Exits   ExitProbe   TimezoneService             │
              │ ExtensionLibrary   ExtStorageSync   Vault   Settings   Sync    │
              │ 本地接口：127.0.0.1:<端口>  HTTP + WebSocket（令牌 + 来源校验）   │
              └───────┬───────────────────────┬──────────────────────┬─────────┘
            启动 / 监视│                        │ 本地接口              │ 控制接口
        ┌─────────────▼──────────┐  ┌──────────▼───────────┐   ┌──────▼──────────┐
        │ 内核进程：实例 #3       │  │ 内核进程：实例 #5     │   │ mihomo（单进程） │
        │ 用户数据目录 profiles/3 │  │ 用户数据目录 profiles/5│   │ in-3 → g-3      │
        │ 伴随扩展 + 主题 + 全局扩展│  │ 伴随扩展 + 主题 + 全局扩展│  │ in-5 → g-5      │
        │ --proxy-server=端口3    │  │ --proxy-server=端口5  │   │ in-util → g-util│
        └───────────┬────────────┘  └──────────┬───────────┘   └──────┬──────────┘
                    └────── socks5 ────────────┴───────────────►      ▼ 各自的出站节点
```

**四条硬规则**

- R-1 实例的浏览器进程**必须**带 `--proxy-server=socks5://127.0.0.1:<端口>` 和 `--host-resolver-rules="MAP * ~NOTFOUND , EXCLUDE 127.0.0.1"` 启动（#0 未开代理时例外）。前者保证所有请求进本地端口，后者保证浏览器自己不做任何 DNS 解析。
- R-2 mihomo 里每个实例的策略组第一项是 `REJECT`。配置重载后、核心服务显式切换前，流量一律被拒。
- R-3 核心服务自身的联网（拉订阅、查 IP 归属、下载扩展、同步）走工具通道；没有可用订阅时才直连。出口探测例外：必须经**被探测实例自己的端口**发出。
- R-4 核心服务的本地接口只监听 `127.0.0.1`，每个请求校验令牌，并校验 `Origin` 为伴随扩展的固定来源。网页无法调用。

**KernelAdapter 接口**（内核无关层）至少包含：内核能力声明（是否支持引擎级指纹、时区开关）；把"实例配置"翻译成启动参数和环境变量；用户数据目录内各类文件的路径（偏好文件、扩展存储目录）。

## 5. 功能规格

### 5.1 实例与窗口（F-INST，P0）

- F-INST-1 启动程序 → 核心服务就绪 → 打开普通窗口 #0。托盘图标菜单：打开普通窗口、实例管理、退出。
- F-INST-2 `Ctrl+M`（伴随扩展的快捷键命令，任何窗口内都有效）：新建一个**全新**实例（新编号、调色板中下一个颜色、新指纹种子、空用户数据目录）并启动其窗口。
- F-INST-3 新实例的代理按全局默认生成：默认订阅；出口按"未被其他实例占用的优先"自动挑一个（策略可改为"不指定"或"每次询问"）；优选 IP 按全局默认的模式（同出口 / 自选，自选时取延迟最低的）；Host 按 8.3 平分。
- F-INST-4 实例启动流程见 8.9。**出口探测完成、时区确定之前不得启动浏览器进程**。
- F-INST-5 实例的识别：窗口边框和标签栏为实例色（每实例生成一个主题）；用户名处显示 `#编号`；伴随扩展按钮显示出口国旗；新标签页居中显示编号、国旗、出口 IP、时区的图标化摘要。
- F-INST-6 实例的所有窗口都关闭 → 进程退出 → 实例**休眠**（保留数据，释放代理端口和出站）。
- F-INST-7 实例管理页（`Ctrl+Shift+M`、托盘菜单、或伴随扩展面板里的入口）：网格展示全部实例（编号、颜色、国旗、运行状态、最近使用时间）。点击 → 未运行则启动，已运行则把它的窗口提到前台。右键菜单：改名、换颜色、重启、删除。
- F-INST-8 删除实例必须二次确认，然后删除其整个用户数据目录。编号不回收。
- F-INST-9 从未访问过任何网址就被关闭的新实例，自动删除。
- F-INST-10 同一实例不得同时运行两个进程；重复启动改为聚焦已有窗口。
- F-INST-11 需要重启才生效的改动（见 D12）发生后，该实例的伴随扩展按钮出现"需重启"标记，点击一键重启。
- F-INST-12 一次性实例（P1）：用临时用户数据目录，进程退出即删除，不进入实例管理页。

### 5.2 隔离与防泄漏（F-ISO，P0）

- F-ISO-1 每个实例一个独立用户数据目录 `profiles/<实例id>/`，由此 Cookie、站点存储、缓存、Service Worker、连接池、DNS 缓存、站点权限、历史记录全部天然隔离。
- F-ISO-2 启动参数满足 R-1。WebRTC 策略为"禁止非代理 UDP"（默认内核自带此默认值；备选内核用启动参数加偏好项双重设置）。
- F-ISO-3 公网页面访问本机和内网地址：依赖内核自带的本地网络访问保护；伴随扩展再加一条网络规则，拦截网页对 `127.0.0.1`、`localhost`、`[::1]` 的请求。
- F-ISO-4 **不一致即断流**：自动时区模式下，核心服务探测到出口的时区与该实例进程启动时所用的时区不同 → 立即把该实例策略组切到 `REJECT`，按钮显示警示，提示一键重启。固定时区模式不受此约束。
- F-ISO-5 代理内核崩溃 → 所有实例端口不可用 → 页面报错；核心服务自动重启代理内核（退避 1、2、5 秒）并恢复各实例选择。任何情况下不得让浏览器改走直连。

### 5.3 代理（F-PROXY，P0）

**基础**

- F-PROXY-1 核心服务启动时拉起一个 mihomo 子进程，只监听 `127.0.0.1`，控制接口带随机密钥。
- F-PROXY-2 每个实例固定分配一个本地端口（创建时分配并保存；启动时若被占用则换一个）。实例运行期间，mihomo 里有它的一条 socks 入站和一个策略组（配置样例见 8.6）。入站关闭 UDP。
- F-PROXY-3 代理开关：开 = 策略组选节点；关 = 选 `DIRECT`（此时真实 IP 暴露，按钮必须用醒目的不同图标表示）；断流 = 选 `REJECT`。切换后关闭该入站上的既有连接。
- F-PROXY-4 普通窗口 #0 默认不带代理参数。在它的节点面板里打开代理开关 → 提示重启 #0 → 之后 #0 与实例使用同一套机制（但不做指纹伪装）。

**订阅**

- F-PROXY-10 支持两种格式：Clash / mihomo YAML（取 `proxies`，字段原样透传）；Base64 或明文 URI 列表（P0 解析 `vless://`、`trojan://`、`ss://`，P1 加 `vmess://` 等）。VLESS 映射见 8.1。
- F-PROXY-11 订阅类型自动判定并允许手动改：全部节点共用同一 uuid/密码、同为 ws+tls、只在 address 和 host 上不同 → 判为 edgetunnel；否则为通用。
- F-PROXY-12 刷新时机：打开节点面板时若距上次成功拉取超过 6 小时，后台静默拉取；核心服务启动时同理；可手动刷新。**内容无变化则什么都不动**；有变化才替换并按 8.2 对账。拉取失败保留旧数据，只显示一个小警示点。
- F-PROXY-13 每个订阅可选"通过代理更新"（走工具通道）。

**edgetunnel 模式**

- F-PROXY-20 从订阅节点提取：模板（公共字段）、优选 IP 列表（去重的 address:port）、Host 池（去重的 host/sni）。
- F-PROXY-21 实例的实际节点 = 模板 + 优选 IP + 分配的 Host + 按出口条目改写后的 path。uuid、ech、tls 参数等完全沿用订阅。
- F-PROXY-22 优选 IP 列表 = 订阅自带（只读，随订阅刷新）+ 用户手动添加（IP 或域名，可带端口和备注）。可一键全部测速。
- F-PROXY-23 Host 池有多个时，按 8.3 在实例之间平均分配，分配后保持不变，除非该 Host 从订阅中消失。
- F-PROXY-24 P0 对 ws 和 xhttp 传输做 path 改写（xhttp 未实连验证，见 decisions P-8）；grpc 节点按通用节点处理。
- F-PROXY-25（**已取消**，由"出口地区"自动配对替代，见 `decisions.md` P-6；以下为原设计）**优选 IP 药丸开关：同出口 / 自选**（每实例一个，全局可设新实例的默认值，初始默认"自选"）。
  - 同出口：address 取所选出口条目的地址（域名展开时取选中的那个 IP），端口取条目自带端口，没有则 443。仅当出口类型为 `proxyip` 时可选。
  - 切到"同出口"时立即经该组合测一次延迟；不通则保持断流并显示错误，**不得自动退回自选的优选 IP**（那会让出口国家悄悄变化）。
  - 出口列表里每个条目测过后显示一个"可作入口"标记，方便挑选。

**出口列表（原稿的 proxyip 列表）**

- F-PROXY-30 全局一份列表。条目：类型（`proxyip` P0；`socks5`、`http` P1）、值（IP、IP:端口、域名、域名:端口，或代理地址）、备注。支持多行粘贴批量导入。
- F-PROXY-31 域名条目有两种用法，可逐条切换：**原样使用**（把域名直接写进 path，由服务端解析）；**展开**（本地解析出域名包含的所有 IP，每个 IP 成为可选子项）。
- F-PROXY-32 展开的域名默认每 3 小时重新解析（间隔可设，可关）。实例选中的 IP 在刷新后消失时：默认只标记失效并提示，**不自动换**（换出口等于换身份）；可在设置里开启"自动换到同域名下的其他 IP"。
- F-PROXY-33 path 改写规则见 8.4，模板可在高级设置里改。
- F-PROXY-34 实例也可以不指定出口（path 保持订阅原样）。

**通用模式**

- F-PROXY-40 展示订阅的节点列表（名称、国旗、延迟），每实例选一个。切换节点用策略组热切换，不重载配置。

**状态展示**

- F-PROXY-50 伴随扩展按钮：图标 = 出口国旗（直连、断流、异常各有专用图标）；角标 = 延迟毫秒数，角标底色绿 / 黄 / 红（<300 / <800 / 其余）。
- F-PROXY-51 鼠标悬停按钮 → 文字详情：节点或优选 IP、两条路径的出口 IP 与国家/城市/运营商、实时上传下载速度、本次与累计流量、当前生效时区、订阅上次更新时间。每 2 秒刷新。
- F-PROXY-52 点击按钮（或 `Alt+P`）→ 节点面板（线框见 6.3）。主体只有三块：订阅、优选 IP、出口 IP；出口一栏标题处有一个小按钮进入出口列表管理。通用模式下后两块合并为节点列表。
- F-PROXY-53 延迟：实例运行期间每 60 秒经 mihomo 测一次，可手动立即测。流量：订阅 mihomo 的连接流，按入站归属到实例。
- F-PROXY-54 两条路径出口国家不一致时，国旗上叠加警示点，悬停详情里说明。

### 5.4 指纹与时区（F-FP，P0）

- F-FP-1 每个实例有一个随机种子。核心服务由它确定性推导出内核需要的 32 位指纹种子和各项取值：同一实例永远不变，不同实例互不相同。
- F-FP-2 默认内核下，以下各项通过启动参数在**引擎层**生效（页面里看不到任何脚本改写痕迹）：

| 项目 | 启动参数 | 默认值 |
|---|---|---|
| Canvas、WebGL 图像、音频、字体、ClientRects、显卡信息、内存 | `--fingerprint=<种子>` | 由种子决定 |
| 操作系统 | `--fingerprint-platform` | **锁定为本机真实系统**（跨系统伪装会与字体、显卡对不上） |
| 浏览器品牌 | `--fingerprint-brand=Chrome` | Chrome，版本用内核真实版本 |
| CPU 核数 | `--fingerprint-hardware-concurrency` | 种子从 {4, 8, 12, 16} 选 |
| 时区 | `--timezone=<IANA 时区>` | 见 F-FP-6 |
| 界面语言 / 接受语言 | `--lang`、`--accept-lang` | 跟随出口国家；可固定 |
| WebRTC | 内核默认禁止非代理 UDP | 保持默认 |
| 单项关闭伪装 | `--disable-spoofing=font,audio,canvas,clientrects,gpu` | 全部开启 |

  【需验证 V3】以所用内核版本的说明为准，逐项实测。
- F-FP-3 普通窗口 #0 不带任何指纹参数。
- F-FP-4 指纹配置面板（伴随扩展面板的"面具"页）：每项一个图标 + 当前值，点击修改；可单项关闭伪装；"重新生成"换新种子，必须二次确认（等于换设备）。任何修改 → 标记"需重启"。
- F-FP-5 自检页（伴随扩展内页面）：展示当前实例的两路出口 IP、时区、语言、UA、WebRTC 候选地址、Canvas 与 WebGL 哈希，并用红绿图标标出不一致项。

**时区**

- F-FP-6 模式：自动 / 固定。自动模式的来源可选：proxyip 出口（默认）/ 直连路径出口。未指定出口条目、使用通用节点、或优选 IP 为"同出口"时，两者通常相同。
- F-FP-7 自动模式的保证方式：启动前先探测出口并据此设定时区（F-INST-4）；运行中每 30 分钟、以及每次换节点 / 优选 IP / 出口、出口列表刷新、系统从睡眠恢复、网络变化时重新探测；结果与启动时所用时区不同 → 按 F-ISO-4 断流并提示重启。
- F-FP-8 代理关闭（直连）且为自动模式 → 时区应为本机时区；若实例是带着别的时区启动的，同样按 F-ISO-4 处理。
- F-FP-9 固定模式的选择器：可搜索的下拉框，列出全部 IANA 时区（显示城市名 + UTC 偏移），**也可以直接输入**，输入值必须校验为合法时区名。

### 5.5 扩展（F-EXT，P0）

**模型**

- F-EXT-1 核心服务维护一份**全局扩展库**。每个扩展有两个独立的药丸开关：

| 开关 | 选项 | 默认 | 含义 |
|---|---|---|---|
| 范围 | 全部实例 / 指定实例 | **全部实例** | 扩展装进哪些实例（含普通窗口 #0） |
| 数据 | 独立 / 共享 | **共享**（新扩展的默认值可在设置里改成独立） | 独立：扩展本体共用，每个实例各存各的配置和缓存。共享：扩展的配置和数据全局一份，在一个实例里改了，其他实例也跟着变 |

- F-EXT-2 只支持 Manifest V3 扩展。

**安装（四个入口，结果相同：进入全局库）**

- F-EXT-3 在 Chrome 应用商店的扩展详情页点伴随扩展按钮 → 面板顶部出现"安装到全局"。
- F-EXT-4 在扩展管理页粘贴商店链接或扩展 ID。
- F-EXT-5 把 `.crx`、`.zip` 或解压后的目录拖进扩展管理页。
- F-EXT-6 用户在某个实例里自行装了扩展 → 伴随扩展检测到 → 自动收进全局库（"自动收录"开关，默认开）。
- F-EXT-7 入库处理见 8.10。关键点：保持扩展 ID 与商店一致。

**生效**

- F-EXT-8 实例启动时，核心服务按"范围"把应装的扩展全部交给内核加载。已在运行的实例需重启才能加载新装的扩展或卸掉被删的扩展（标记"需重启"）。
- F-EXT-9 独立模式：不做任何处理，天然如此。
- F-EXT-10 共享模式：核心服务为该扩展保存一份"主数据"，在**实例启动前**把主数据拷入该实例，在**实例退出后**把该实例里变化过的数据拷回成为新的主数据。算法见 8.11。
- F-EXT-11 共享模式的边界，必须在开关旁用提示图标说明：
  - 两个实例同时开着时不会实时互通；A 里改的配置，B 要重启后才看到。
  - 两个实例都改了同一个扩展 → 后退出的覆盖先退出的（以整个扩展为单位）。
  - 带账号登录或设备标识的扩展（钱包、密码管理器、需要登录的工具）一旦共享，其服务商会看到同一身份从多个出口出现。这类扩展应改为"独立"。由于默认值是共享，入库时若扩展申请了 `identity`、`cookies` 这类权限，必须在它的卡片上提示用户考虑改为独立。
- F-EXT-12 "立即同步"按钮（P1）：把当前实例的数据推成主数据，并给其他运行中的实例打上"需重启"标记。
- F-EXT-13 实时互通（P2）：经调试接口监听扩展的 `chrome.storage` 变化并转发到其他实例，仅覆盖 `chrome.storage`。做之前须单独验证。
- F-EXT-14 更新：每周经工具通道检查商店版本，有新版自动替换库内文件，下次启动实例时生效。

**油猴**

- F-EXT-15 把 Tampermonkey 装进全局库，保持默认的"共享"数据模式，即得到"脚本全局只维护一份"。【需验证 V7】油猴所需的"允许用户脚本"开关能否由核心服务预先打开；不能则在新实例首次启动时引导用户点一次。

**扩展管理页**

- F-EXT-16 卡片网格：图标、名称、版本、范围药丸、数据药丸、启用开关、删除。范围选"指定实例"时展开一排实例色块供勾选。

### 5.6 密码管理（F-PWD，P1）

- F-PWD-1 全局一个保险库，由核心服务保管。每条记录：站点（协议 + 主机 + 端口）、用户名、密码、**所属实例编号**（在哪个实例里保存的）、备注、时间戳。
- F-PWD-2 内核自带的密码保存和自动登录通过偏好项关闭，避免重复弹窗。
- F-PWD-3 捕获（伴随扩展的内容脚本）：检测登录表单提交，包括无表单的脚本登录（点击按钮或回车时页面上有已填的密码框）。默认**自动保存**，按钮上闪一个钥匙标记并可撤销；同站点同用户名则更新密码。可改为"每次询问"。站点可加入"永不保存"。
- F-PWD-4 填充：页面出现登录框时，若"该站点 + 当前实例"恰有一条记录则自动填入；有多条或只有其他实例的记录时，聚焦输入框弹出下拉（当前实例的排前，每条带 `#编号` 彩色标记），点击才填。
- F-PWD-5 安全：只在站点完全匹配时填充；默认不向跨域内嵌框架填充；下拉界面放在扩展自己的内嵌页面里，网页脚本读不到；HTTP 站点填充前提示。
- F-PWD-6 存储：保险库整体加密落盘，密钥交给系统凭据保护（Windows 用 DPAPI）。可选主密码。
- F-PWD-7 管理页：按实例编号或按站点分组，搜索，查看 / 复制（30 秒后清空剪贴板），编辑，删除，改所属实例，生成随机密码，导入导出 Chrome 格式 CSV。
- F-PWD-8 随同步加密传输。

### 5.7 全局设置（F-SET，P0）

- F-SET-1 分层：

| 全局（改一处，所有实例生效） | 每实例独立 |
|---|---|
| 搜索引擎（默认 Bing）、启动时恢复上次页面、下载目录、界面深浅色 | 编号、名称、颜色 |
| 订阅列表、出口列表、自定义优选 IP 列表 | 代理开关、所选订阅、优选 IP 模式与取值、Host、出口 |
| 全局扩展库及每个扩展的两个开关 | 指纹种子与各项取值 |
| 密码保险库、书签（P1） | 时区模式与值、语言模式 |
| 新实例的默认代理、默认优选 IP 模式、默认指纹设置 | Cookie、站点存储、缓存、历史记录、站点权限 |
| 同步配置、节点域名解析用的 DNS | 是否随同步携带登录状态（P2） |

- F-SET-2 实现方式：核心服务维护一份"受管偏好项"清单。**每次启动实例前**，把全局值和该实例的派生值合并写入其用户数据目录的偏好文件（只改清单内的键，其余原样保留）。因此在我们的设置页改全局项，对未运行的实例下次启动生效，对运行中的实例标记"需重启"。【需验证 V8】所用内核不会把被改写的偏好项重置。
- F-SET-3 受管清单（P0）：恢复上次会话、下载目录、关闭自带密码管理、接受语言、WebRTC 策略、用户名显示为 `#编号`、关闭首次运行和默认浏览器提示。
- F-SET-4 默认搜索引擎为 Bing：新标签页由伴随扩展接管，搜索框直接提交到 `https://www.bing.com/search?q=…`；地址栏的默认搜索引擎通过伴随扩展的搜索引擎覆盖声明设置，不可行则写偏好文件。【需验证 V7】
- F-SET-5 不在受管清单里的浏览器设置（内核自己的设置页）按实例各自保存。这一点须在设置页注明。
- F-SET-6 书签全局统一（P1）：核心服务保存主书签，伴随扩展用书签接口在各实例间增量应用。

### 5.8 会话恢复（F-SESSION，P0）

- F-SESSION-1 每个实例的标签恢复使用内核原生能力：偏好项设为"继续上次浏览"，并带强制恢复上次会话、隐藏崩溃恢复气泡的启动参数。正常关闭、异常关闭、断电后都应恢复。
- F-SESSION-2 核心服务记录"退出时哪些实例正在运行"（状态变化即写盘）。下次启动程序时，默认把这些实例全部重新打开（可改为"只开普通窗口"）。
- F-SESSION-3 核心服务用运行锁文件识别自身的异常退出，处理方式与正常退出相同。启动时必须清理上次遗留的孤儿内核进程和孤儿 mihomo 进程。

### 5.9 同步（F-SYNC，P2）

- F-SYNC-1 同步内容：全局设置、订阅、出口列表、自定义优选 IP、实例元数据（编号、名称、颜色、指纹种子、代理选择、时区设置）、密码保险库、书签、全局扩展清单（扩展 ID、范围、数据模式）。
- F-SYNC-2 默认**不**同步：Cookie 与站点存储、历史、扩展本体。"携带登录状态"为每实例可选项，开启时提示风险（不同设备指纹不同，可能触发网站风控）。
- F-SYNC-3 数据在本地加密后上传，服务端只见密文。
- F-SYNC-4 后端二选一：**自建 Cloudflare Worker + KV**（仓库提供脚本，见 8.8）；**WebDAV**。接口抽象为三个操作：取元信息、取快照、带版本条件地写快照。
- F-SYNC-5 配对：电脑端显示二维码（内含地址和密钥），手机扫码即完成；也可手动填"地址 + 口令"。
- F-SYNC-6 流程（按原稿思路）：一端点"上传"；另一端在启动、回到前台、以及每 30 分钟各查一次元信息（一个极小的请求），发现新版本则同步图标出现"有更新"标记，点击拉取并合并。若上传时发现远端已被别人更新 → 图标变为"需合并"，点击后先拉取、按 8.7 合并、再上传。
- F-SYNC-7 同步图标的五种状态：已同步、本地有改动待上传、远端有更新、需合并、出错。
- F-SYNC-8 每台设备每天的请求量应在 100 次以内。
- F-SYNC-9 隧道直连（电脑临时起服务 + cloudflared 临时隧道 + 扫码）作为第三种后端，P2 之后再评估；cloudflared 按需下载，不打进安装包。

## 8. 关键算法与流程

### 8.1 VLESS 链接 → mihomo 出站

```
vless://<uuid>@<server>:<port>?security=tls&sni=<sni>&fp=<fp>&alpn=<alpn>
        &type=ws&host=<host>&path=<URL编码的path>&allowInsecure=<0|1>&ech=<…>#<名称>
```

```yaml
- name: <名称>
  type: vless
  server: <server>
  port: <port>
  uuid: <uuid>
  udp: false
  tls: true
  servername: <sni，缺省用 host>
  client-fingerprint: <fp，缺省 chrome>
  skip-cert-verify: <allowInsecure == 1>
  network: ws
  ws-opts:
    path: <解码后的 path>
    headers: { Host: <host> }
  # ech 参数映射到 ech-opts【需验证 V5】
```

`trojan://`、`ss://` 按 mihomo 文档的对应字段映射。YAML 订阅的 `proxies` 项直接作为 `raw`，不做转换。必须有覆盖三种协议的解析单元测试。

### 8.2 订阅刷新与对账

1. 拉取 → 解析 → 把节点按 `key` 排序后计算 `contentHash`。
2. 与旧值相同：只更新 `fetchedAt`，结束。
3. 不同：替换节点、模板、Host 池、订阅来源的优选 IP。
4. 对每个使用该订阅的实例对账：
   - （优选 IP 为"自选"模式时）所选优选 IP 仍在 → 不动；不在 → 换成延迟最低的，并在该实例的工具栏按钮上给出提示。
   - 所分配 Host 仍在 → 不动；不在 → 按 8.3 重新分配。
   - 通用模式的 `nodeKey` 仍在 → 不动；不在 → 该实例断流（策略组切到 REJECT）并提示，不自动换节点，也不回落直连。
5. 所有受影响实例合并为**一次**代理内核配置重载。

### 8.3 Host 平均分配

统计该订阅下所有实例当前各 Host 的使用数，取最少的；并列时用实例种子做确定性选择。分配后保持不变，仅在该 Host 消失时重新分配。

### 8.4 path 改写

输入：模板的 `basePath`（例如 `/?ed=2560`）和出口条目。

1. 把 `basePath` 拆成路径部分和查询串。**输出时不得做 URL 编码**（`?`、`:`、`@`、`/` 保持原样）。
2. 清除已有的出口参数：查询键 `proxyip`、`socks5`、`http`；以及以 `/proxyip=`、`/proxyip.`、`/socks5=`、`/socks5://`、`/socks://`、`/http=`、`/http://` 开头的路径段。
3. 按类型套模板（模板可在高级设置里改）：

| 类型 | 默认模板 | 备选模板 |
|---|---|---|
| proxyip | `{路径}?proxyip={值}{&其余查询}` | `/proxyip={值}{?其余查询}` |
| socks5（全局） | `/socks5://{值}{?其余查询}` | — |
| http（全局） | `/http://{值}{?其余查询}` | — |
| 不指定 | `basePath` 原样 | — |

示例：`/?ed=2560` + proxyip `10.28.138.41` → `/?proxyip=10.28.138.41&ed=2560`。

4. 【需验证 V5】用真实部署确认默认模板生效；不生效则切换备选模板并记录。

### 8.5 出口探测与时区

探测由核心服务发起，请求**经被探测实例的本地代理端口**发出（实例未运行时，临时把它的入站和出站加入 mihomo 再探测）：

- CF 路径：`https://www.cloudflare.com/cdn-cgi/trace` → 取 `ip`、`loc`。
- 直连路径：`https://checkip.amazonaws.com` → 取 IP。

再经工具通道查两个 IP 的归属（国家、城市、时区、运营商）。查询端点做成可配置列表，依次回退；结果按 IP 缓存 7 天。全部失败时，用打包的"国家 → 默认时区"表兜底（多时区国家取首都所在时区，并标记为"近似"）。

时区取值：`tz.mode = fixed` 用固定值；否则按 `tz.source` 取对应出口的时区；代理为直连时取本机时区。国旗显示 `tz.source` 对应出口的国家；两路国家不同则加警示点。

直连路径的 IP 属于 Cloudflare 的共享出口池，可能变动，界面上以国家和运营商为主展示。

### 8.6 代理内核配置生成

由核心服务的状态**整体生成**，不手工增量修改。示例：

```yaml
allow-lan: false
bind-address: 127.0.0.1
mode: rule
log-level: warning
external-controller: 127.0.0.1:<控制端口>
secret: <随机密钥>

dns:                      # 用于解析节点自身的域名，以及直连状态下的网页域名
  enable: true
  nameserver: [<设置里的 DoH 地址>]

proxies:
  - { name: n-<实例id>, type: vless, server: <优选IP 或 出口地址>, port: 443, uuid: <…>, tls: true,
      servername: <host>, client-fingerprint: chrome, udp: false, network: ws,
      ws-opts: { path: "/?proxyip=10.28.138.41&ed=2560", headers: { Host: <host> } } }
  - { name: s-<订阅id>-0, … }        # 通用订阅的节点，每个定义一次
  - { name: probe-<订阅id>-<序号>, … } # 仅在"全部测速"时临时加入

proxy-groups:                         # 第一项必须是 REJECT
  - { name: g-<实例id>, type: select, proxies: [REJECT, n-<实例id>, DIRECT] }              # edgetunnel 实例
  - { name: g-<实例id>, type: select, proxies: [REJECT, s-<订阅id>-0, s-<订阅id>-1, DIRECT] } # 通用实例
  - { name: g-util,     type: select, proxies: [DIRECT, <默认订阅当前节点>] }

listeners:
  - { name: in-<实例id>, type: socks, listen: 127.0.0.1, port: <端口>, udp: false, proxy: g-<实例id> }
  - { name: in-util,     type: socks, listen: 127.0.0.1, port: <端口>, udp: false, proxy: g-util }

rules:
  - MATCH,REJECT            # 兜底：任何未绑定的流量一律拒绝
```

应用流程：状态变化 → 防抖 300 毫秒 → 写 `core/config.yaml` → 调用重载接口 → 读回确认 → **逐个实例把策略组切到它应有的选项**（开 = 节点，关 = DIRECT，断流 = 保持 REJECT）。

- 代理开关、通用实例换节点：只调用策略组切换接口，不重载。
- edgetunnel 实例换优选 IP / 出口 / 优选 IP 模式：出站定义变了，需要重载。【需验证 V6】确认重载不打断其他实例的长连接；若会打断，改为把每个实例近期用过的组合都预先写成出站，用策略组切换。
- 流量归属：连接流里每条连接的元数据带入站信息，按入站名归到实例。【需验证 V6】字段名；备选按连接链里的策略组名归属。

### 8.7 同步合并

- 每条可同步记录带 `id`、`updatedAt`、`deleted`。全局设置按"每个键一个时间戳"处理。
- 时间戳用混合逻辑时钟（取本机时间与已见最大时间戳的较大者再加 1），避免两台设备时钟不准。
- 合并 = 按 `id` 取并集，同一条取 `updatedAt` 较大者（相同则设备 id 大者胜）。删除用墓碑记录，保留 90 天。
- 密码记录若两端自上次同步后都改过：新的胜出，旧密码追加进该条的 `history`。
- 合并结果先落本地，再与远端比较，不同才上传。
- 上传带"我基于的版本号"；服务端版本号不匹配则拒绝（返回 412），客户端转入"需合并"状态。

### 8.8 同步 Worker（随仓库提供，约百行）

```
GET  /v1/<sid>/meta   → 200 { v, at, device, size, sha256 } ｜ 404
GET  /v1/<sid>/blob   → 200 密文，响应头 ETag: "<v>"
PUT  /v1/<sid>/blob   请求头 If-Match: "<v>"（首次用 If-None-Match: *）
                      → 200 { v: v+1 } ｜ 412 版本冲突 ｜ 413 超过 5 MB
全部接口要求 Authorization: Bearer <token>；首次写入时服务端记下 token 的哈希，之后比对。
```

密钥推导：`主密钥 = Argon2id(口令, 盐 = SHA-256(地址))`；再用 HKDF 分别导出 `sid`、`token`、`加密密钥`。快照 = JSON → gzip → AES-256-GCM（或 XChaCha20-Poly1305）。用户只需记"地址 + 一个口令"；二维码里直接放地址和主密钥。

说明：KV 不提供严格的原子比较写入，单人两三台设备的场景可接受；要严格可换 D1。

### 8.9 实例启动流程

1. 若该实例已在运行 → 通知其伴随扩展聚焦窗口，结束。
2. 确认端口可用；把该实例的入站、出站、策略组加入 mihomo 配置并重载；策略组停在 `REJECT`。
3. 代理状态为"开" → 策略组切到节点 → 按 8.5 探测出口。探测失败 → 不启动，报错（固定时区模式下可由用户选择强行启动）。
4. 确定时区（8.5）和语言。
5. 准备用户数据目录：按 F-SET-2 合并写入受管偏好项；对"范围"包含本实例且数据模式为"共享"的每个扩展，按 8.11 把主数据拷入。
6. 生成本实例的伴随扩展副本（写入 `config.json`：实例 id、编号、颜色、核心服务端口、令牌）和主题目录（边框色 = 实例色）。
7. 组装启动参数（默认内核示例）并启动进程：

```
--user-data-dir=<profiles/实例id>
--proxy-server=socks5://127.0.0.1:<端口>
--host-resolver-rules="MAP * ~NOTFOUND , EXCLUDE 127.0.0.1"
--load-extension=<伴随扩展>,<主题>,<全局扩展1>,<全局扩展2>,…
--fingerprint=<32位种子> --fingerprint-platform=<本机系统> --fingerprint-brand=Chrome
--fingerprint-hardware-concurrency=<核数> --timezone=<时区>
--lang=<语言> --accept-lang=<语言列表>
--restore-last-session --hide-crash-restore-bubble --no-first-run --no-default-browser-check
```

   普通窗口 #0：不带指纹和时区参数；未开代理时也不带前两个代理参数。
8. 记录本次启动所用的时区、参数哈希、扩展集合哈希（用于之后判断"需重启"和"不一致即断流"）。
9. 监视进程。退出后：按 8.11 回写共享扩展数据 → 从 mihomo 移除该实例的入站出站 → 标记休眠。

### 8.10 扩展入库

1. 取得扩展包：商店来源经工具通道按扩展 ID 下载 `.crx`【需验证 V7：下载地址可用】；文件来源直接读取。
2. 解析 CRX 头，取出公钥；解压出文件。
3. 在 `manifest.json` 里写入 `key` 字段（公钥的 Base64），使解包加载后的扩展 ID 与商店 ID 相同。
4. 删除 `_metadata` 目录（解包加载不允许存在以下划线开头的保留目录）。
5. 校验 `manifest_version` 为 3，否则拒绝并提示。
6. 存入 `extensions/<扩展id>/<版本>/`，登记到 `extensions.json`，范围和数据取默认值。
7. 给"范围"内所有运行中的实例打"需重启"标记。

### 8.11 共享模式的扩展数据同步

每个扩展在一个用户数据目录里的数据位置，由 `KernelAdapter` 给出。预期包括【需验证 V8】：

```
Default/Local Extension Settings/<扩展id>/
Default/Sync Extension Settings/<扩展id>/
Default/IndexedDB/chrome-extension_<扩展id>_0.indexeddb.leveldb/   （及同名 .blob 目录）
Default/DNR Extension Rules/<扩展id>/
```

- **拉（实例启动前）**：若 `ext-master/<扩展id>/` 存在且其版本号大于该实例上次同步的版本号 → 用主数据整体替换该实例里上述目录。
- **推（实例退出后）**：计算该实例上述目录的内容哈希；与启动时拉入后的哈希不同 → 说明本次运行改过数据 → 整体复制为新的主数据，版本号加 1，并记下"来自哪个实例、何时"。
- 复制一律"先复制到临时目录再改名"，中途失败不得留下半份数据。
- 只能在该实例的浏览器进程**完全退出后**读写这些目录（运行时数据库被锁定）。
- 冲突策略：以整个扩展为单位，后推的覆盖先推的；被覆盖的主数据保留最近 3 份备份，扩展管理页可回滚。
- 把一个扩展从"独立"改为"共享"时：让用户选一个实例作为初始主数据来源。从"共享"改回"独立"：各实例保留当前数据，此后不再同步。

## 10. 技术栈与工程结构

- **核心服务**：Go（最新稳定版）。依赖尽量只用标准库；托盘用一个轻量托盘库。Windows 为首要平台，macOS / Linux 顺带产出。

- **测试**：Go 自带测试（纯逻辑包必须有单元测试）；端到端用脚本启动真实实例并访问自建检测页。

## 13. 风险清单

| 风险 | 影响 | 对策 |
|---|---|---|
| 默认内核是个人维护的第三方构建 | 停更、落后于安全更新、供应链信任 | 内核可插拔；校验哈希；每次升级复测 V2–V4；必要时自行编译或换备选内核 |
| 内核升级改变启动参数或目录结构 | 指纹参数失效、共享数据同步失效 | 全部收在 `KernelAdapter`；升级后跑 V3、V7、V8 |
| 误以为 proxyip 决定所有出口 | 时区与 Google 所见 IP 不一致 | 双路探测、警示点、"同出口"模式、时区来源可选（3.2） |
| 共享模式下扩展数据互相覆盖 | 配置丢失 | 以扩展为单位保留 3 份备份可回滚；界面明示边界 |
| 共享带身份的扩展 | 实例被扩展服务商关联 | 默认共享是需求方的选择；入库时对申请身份类权限的扩展提示改为独立 |
| 所有实例装同一批扩展 | 网站可探测到相同的扩展组合（弱关联信号） | 范围可改为指定实例；在设置页说明 |
| 订阅或出口变化导致身份漂移 | 账号风控 | 出口失效只提示不自动换；Host 分配保持不变；不一致即断流 |
| 内存占用随打开的实例数线性增长 | 机器吃紧 | 关窗即休眠；M0 实测后给出建议的同时打开数量 |
| Android WebView 能力受限 | 手机端伪装弱 | 明确告知；VA1、VA2 先行；GeckoView 备选 |
| 使用合规 | 账号被封、法律风险 | 仅用于管理本人合法持有的账号，遵守目标网站条款和当地法律 |
