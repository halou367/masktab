## 2026-11-16：IPv6 的优选 IP 用不了、域名解析不全（decisions N-2）

需求方：填 `2606:4700:5a:8e48:1c8d:85bf:712a:164f` 和 `v6.629717.cc.cd` 这样的优选地址，节点显示“解析失败”；反代列表里域名的 IP 也没有解析全。

- 在沙箱里复现了：假 edgetunnel 监听 `[::1]`，直接探测 1 ms 通，但实例一用它就报“域名解析失败”。代理内核日志是 `dns resolve failed: ip version error`。
- 原因：给代理内核的配置里写着 `ipv6: false`，内核直接拒绝连 IPv6 地址；我们又把这句日志翻译成了“域名解析失败”。地址本身和 DNS 都没有问题。
- 域名解析不全有三处：有 IPv4 就把 IPv6 全丢掉；不查 TXT 记录（edgetunnel 的反代域名常把“IP:端口”放在 TXT 里，服务端也是先看 TXT）；IPv6 加端口拼成 `::1:8443`（变成另一个地址）。
- 改法见 N-2：打开内核的 IPv6；新的解析（TXT、A、AAAA 都查，系统 DNS 加两个公共 DNS 取并集）；IPv6 的写法统一成 `[IPv6]:端口`；解析失败把原因写在地址库那一行；
  连不上 IPv6 时写“本机网络没有 IPv6”；界面上 IPv6 写全、在冒号后折行。
- 已验证（沙箱，Linux）：改完后同一个 `[::1]` 入口实例正常出网，流量确实走 IPv6；只有 AAAA 的域名带端口展开成入口和反代都对；`v6.629717.cc.cd` 解析出 5 个地址；
  `proxyip.cmliussss.net` 解析出 50 个。`go test` 全过，页面检查 114 项通过（新增 8 项）。
- 没验证：沙箱没有公网 IPv6，`2606:4700:…` 这些地址没有真的连通过（显示“本机网络没有 IPv6”）；Windows 和手机上没有试；电脑弹窗里 IPv6 一行的样子没有截图看过；
  需求方说的“没解析全”的那个域名不知道是哪个，不能确定就是上面三处之一。
- CI 的 Windows 机器换了镜像（windows-2025-vs2026），不再自带 NSIS，`choco install nsis` 时灵时不灵：运行 43881369841（重跑后通过）、43885836953（main，没出 Release）
  都死在“找不到 makensis”。`ci.yml` 改成：自带的 → choco 试两次 → 官方便携包 nsis-3.11.zip（校验 SHA-256）。
- 顺带修了 UI-13 的一个真问题：电脑弹窗里打字时，后台刷新的重画会把搜索框的焦点弄丢（CI 运行 43877532143 因此失败）。见 UI-13 末尾的“补”。

## 2026-11-16：手机 Turnstile 600010 修复（decisions A-10）

需求方：手机直连能过、一开代理就 600010（ip.net.coffee/cloudflare）；诊断开关全关也不过；同一节点电脑能过。

- **根因（沙箱用官方火狐 160 复现并按项二分，报告在工作区 turnstile-diag/REPORT.md）**：`fp.js` 用内容脚本改了主线程的 `navigator.language(s)`，Worker 里改不到，
  主线程 ko-KR / Worker 系统语言，Turnstile 一比就判 600010。只在开代理时出现，是因为代理关掉时核心服务不下发语言（`expectTZ`）。

- **改了什么**：
  - `Core.kt` 新增 `applyLocale()`：按当前显示的实例调 `GeckoRuntimeSettings.setLocales`（内核原生：主线程、Worker、Accept-Language、Intl 一起变）。

## 已知问题

1. **共享扩展数据版本号多加**：实例没改动就关闭，主副本版本号仍 +1、多一个备份。原因是 LevelDB 文件一打开就变。要在 `internal/extlib` 的 `Push` 里改进变化检测。
2. **“mihomo 起不来时是否切断”没测准**：杀掉 mihomo 后它 1 秒就自动重启了，页面照常打开。需要让 mihomo 保持起不来再测一次，确认页面打不开而不是直连。
3. （已处理）首次下载没有界面：现在用系统浏览器打开进度页，完整安装包则不需要下载，见 decisions D-1、D-2。
   下载源是 GitHub，可以在设置里填镜像前缀（`mirror`），但设置界面要等内核下载完才打得开——所以还需要一个不依赖内核的进度 / 设置入口，
   或者支持手动把内核解压到 `data/kernel/` 下（现在已经支持：放进去就会被找到）。
4. （已处理）每次启动第一个标签页上的提示条“不受支持的命令行标记：--host-resolver-rules=…”：参数保留（防 DNS 泄漏），
   加 `--test-type` 让内核不出这条提示，见 decisions U-3。新标签页底部还有一条内核加的署名栏，暂时去不掉。
5. （已处理）新标签页接管提示：改用 `--custom-ntp`，不再弹窗，见 decisions U-1。同时发现并停止了对“受保护偏好”的写入，见 U-2。
6. `subscriptions[].template.basePath` 在接口返回里曾经是空的，生成的路径是对的，没有再查。
7. `internal/core` 和 `internal/probe` 没有单元测试。

### 2026-11-14 修：两步登录记不住 / 不自动填（用户在 arena.ai 反馈）
