### 分支 fix/stable-identity：实例身份固定、出口稳定（decisions SI-1，还没合并、没发版）

需求方的话：“每个实例在 arena.ai（以及其他 Cloudflare 站点）验证过一次、登录之后，就像 Cent 浏览器那样尽量不再弹人机验证，即使换了 IP 也一样。”

- **实测**：arena 的放行凭证绑的是出口 IP，不是指纹。同一个 IP 上重启、改时区语言、换指纹种子、关显卡伪装都不弹；换 IP 每次都要重新检测（有时静默、有时弹框）。
- **改**：时区和语言第一次连上可信出口时固定下来，之后不跟出口变（“跟随出口”改成可选，写明代价）；不再拿 Cloudflare Workers 的出口（104.28.x）定时区（以前更新重启后会先变成东京 / 达卡再变回来）。
- **改**：出口“自动”时，当前出口只要真连还通就不换（以前后台扫描一次没测通，下次启动就换 ProxyIP）。
- **新增**：CF 网站看到的出口换了会提示“可能要再验证一次”；一致性检查多一项“CF 网站出口固定”（走 Cloudflare 自己的出口时不过）。
- **改**：新实例默认不伪装显卡（老实例不动）；库里扩展的内容脚本不再进 Cloudflare 验证框。
- **已知代价**：升级内核后所有网站的放行会一起失效一次（UA 版本号变了）。
- 检查：Go 测试（`ident_test.go` 等）、`pages` 全部；需求方 Windows 开发版实测见 SI-1。

### 分支 fix/autofill-email：登录弹窗里的邮箱框自动填、下拉只有本实例的、下拉不再闪（decisions M-7，还没合并、没发版）

需求方的话：“这个页面需要我填写邮箱，应该自动填写我默认邮箱才对，会出现下拉栏是所有实例的邮箱，但是应该只是当前实例的，而且下拉栏会闪烁一下就消失很奇怪，你复测一下。”（arena.ai 的登录 / 注册弹窗，只有一个邮箱框）

- **修**：只有邮箱框、没有密码框的那一步（登录弹窗、两步登录 / 注册的第一页）点进去就填本实例自己的邮箱：信箱的邮箱 > 本实例在这个网站的账号 > 实例自己的邮箱 > 默认邮箱。只填不提交，用户输入过的不覆盖，可撤销。
- **修**：下拉里不再出现别的实例的账号和邮箱（核心服务就不给了）；只列本实例在这个网站的账号、信箱邮箱、默认邮箱，去重。
- **修**：下拉不再一出来就消失（原因是我们自己在焦点离开关闭按钮时定的计时器）；只在点别处、按 Esc、换到别的框时收起；点下拉里的选项不会把网页的弹窗关掉；Esc 只收下拉。
- `/api/vault/match` 多了 `cands`、`mailEmail`，`items` 只有本实例的。
- 检查：Go 测试（只给本实例、邮箱顺序）；`rec-test` 第十段（仿 arena 弹窗：自动填、下拉只有本实例的、2 秒后还在、Esc、点别处、不覆盖、信箱实例）。需求方 Windows 开发版上用 arena.ai 实测过（M-7 里写了）。
- **没验证**：手机；Firefox（交给 CI）。

### 分支 feat/mailbox：信箱（decisions MB-1，还没合并、没发版）

需求方的话：“帮我增加一个信箱管理的功能，有邮件会通知我我可以点击查看……我对实例1添加两个信息一个是卡密，一个取件地址，然后之后取件地址里面有新的邮件就会有通知提示告诉我我点击就可以查看，这样我每一个实例都可以有一个简易的收件取件插件了。邮箱导入的时候也可以识别卡密自动导入创建一个实例并且记住卡密方便使用。”

- **新增**：每个实例可以设一张卡密（Outlook 四段 / 单独的 iCloud 邮箱）和取件地址（默认 email.nloop.cc）；卡密加密存进密码库，界面上只看得到脱敏的样子。
- 后台每 2 分钟（可改）收一次信，按邮件 id 去重，新邮件进未读。**收信走这个实例自己的线路**；实例没开 / 断网时不收、不回落直连（MB-1 里写了代价）。
- 信箱页：收件箱 / 垃圾箱、发件人、主题、时间、未读点、详情、验证码一键复制；正文在不跑脚本的沙盒里，远程图片默认不加载。
- 通知：电脑弹系统通知、工具栏角标写未读数，点通知直接打开那一封；手机**只有应用内提示**（新标签页一行、实例卡片未读数），系统通知要改 Kotlin，记成待办。
- 导入邮箱认得卡密行：每行建一个实例（以邮箱命名），卡密存进密码库；自动填写用实例自己的邮箱（M-6 本来就是这样）。
- 检查：Go 测试（解析、去重、脱敏、加密落盘、接口、经实例通道收信）；`pages mail` 22 项；`ext-e2e` 加 6 项（真扩展弹通知）。
- `/api/state` 每个实例多一个可选的 `mail`、设置多一个 `mailPollMin`（都是 omitempty）；`fixture-state.json` 没重抓，页面检查里的信箱数据是在 `preview-pages.mjs` 里加的。
- **没验证**（第一版）：真取件接口 + 真卡密；Windows 上的通知；手机。2026-11-19 在需求方 Windows 开发版上实测过一轮（项目工作区 `mailbox-real-test-2026-11-19.md`），首次收信超时，见下。

第二轮（2026-11-19 下午，需求方看了实测后的话：“好奇怪，我不开怎么看得到这句话呢，逻辑帮我理顺一下噢；看邮件没事，可以加载图片，点击链接新建标签跳转打开就可以了，就像真的邮件一样，已读、未读等等考虑周全一点。”）：

- **修**：第一次收信必定超时（取件站第一次查一个邮箱要四十多秒，原来只等 30 秒）→ 等 90 秒；线路偶尔断一下自动重试一次；回复传一半断开时按网络错误说明。
- **修**：实例没开时信箱页还写“实例还在启动”。原因：那句提示是后台循环记下来、落盘的“上次的原因”，不是实例现在的状态。现在线路状态每次现算，一次只显示一种提示：没开（灰条 + “打开实例”，立即收信置灰）/ 启动中 / 线路连接中 / 正在收信（文件夹和秒数）/ 上次收信 hh:mm；偶发失败连续 3 次才显示红条。线路一通马上收，不等下一轮。
- **改**：收到的信（列表 + 正文）加密缓存在本机，实例关着、程序重启后照样能看，只是不收新信。
- **改**：远程图片默认直接加载（设置里可改成“询问”）；正文里的链接在当前实例新开标签页打开（iframe 只多给了弹出新标签页的权限，脚本照样不跑）。
- **新增**：标为已读 / 未读（详情、列表行、多选批量）、全部标为已读、本地删除（可撤销）、搜索；标签上的未读数；读过的信通知中心里那条自动收掉；点通知复用已经开着的信箱页；预览里的 `&nbsp;` 这类实体解开；正文加载时有提示。
- 状态里的 `mail` 多了 `line`、`keys`；`err` 只在连续失败 3 次后才有。设置多一个 `mailImages`。新接口 `POST /api/mail/{id}/hide`，`/read` 多了 `unread`。
- 检查：Go 测试加线路状态、连续失败、缓存、标未读、本地删除；`pages mail` 37 项；`ext-e2e` 加“读过以后通知收掉、标未读后未读数回来”。

## 2026-11-16：IPv6 的优选 IP 用不了、域名解析不全（decisions N-2）

需求方：填 `2606:4700:5a:8e48:1c8d:85bf:712a:164f` 和 `v6.629717.cc.cd` 这样的优选地址，节点显示“解析失败”；反代列表里域名的 IP 也没有解析全。

- 在沙箱里复现了：假 edgetunnel 监听 `[::1]`，直接探测 1 ms 通，但实例一用它就报“域名解析失败”。代理内核日志是 `dns resolve failed: ip version error`。
- 原因：给代理内核的配置里写着 `ipv6: false`，内核直接拒绝连 IPv6 地址；我们又把这句日志翻译成了“域名解析失败”。地址本身和 DNS 都没有问题。
- 域名解析不全有三处：有 IPv4 就把 IPv6 全丢掉；不查 TXT 记录（edgetunnel 的反代域名常把“IP:端口”放在 TXT 里，服务端也是先看 TXT）；IPv6 加端口拼成 `::1:8443`（变成另一个地址）。
- 改法见 N-2：打开内核的 IPv6；新的解析（TXT、A、AAAA 都查，系统 DNS 加两个公共 DNS 取并集）；IPv6 的写法统一成 `[IPv6]:端口`；解析失败把原因写在地址库那一行；
  连不上 IPv6 时写“本机网络没有 IPv6”；界面上 IPv6 写全、在冒号后折行。
- 已验证（沙箱，Linux）：改完后同一个 `[::1]` 入口实例正常出网，流量确实走 IPv6；只有 AAAA 的域名带端口展开成入口和反代都对；`v6.629717.cc.cd` 解析出 5 个地址；
  `proxyip.cmliussss.net` 解析出 50 个。`go test` 全过，页面检查 114 项通过（新增 8 项）。
- 没验证：沙箱没有公网 IPv6，`2606:4700:…` 这些地址没有真的连通过（显示“本机网络没有 IPv6”）；Windows 和手机上没有试；电脑弹窗里 IPv6 一行的样子没有截图看过；
  需求方说的“没解析全”的那个域名不知道是哪个，不能确定就是上面三处之一。

## 2026-11-16：手机 Turnstile 600010 修复（decisions A-10）

## 已知问题

1. **共享扩展数据版本号多加**：实例没改动就关闭，主副本版本号仍 +1、多一个备份。原因是 LevelDB 文件一打开就变。要在 `internal/extlib` 的 `Push` 里改进变化检测。
2. **“mihomo 起不来时是否切断”没测准**：杀掉 mihomo 后它 1 秒就自动重启了，页面照常打开。需要让 mihomo 保持起不来再测一次，确认页面打不开而不是直连。
3. （已处理）首次下载没有界面：现在用系统浏览器打开进度页，完整安装包则不需要下载，见 decisions D-1、D-2。
   下载源是 GitHub，可以在设置里填镜像前缀（`mirror`），但设置界面要等内核下载完才打得开——所以还需要一个不依赖内核的进度 / 设置入口，
   或者支持手动把内核解压到 `data/kernel/` 下（现在已经支持：放进去就会被找到）。
4. （已处理）每次启动第一个标签页上的提示条“不受支持的命令行标记：--host-resolver-rules=…”：参数保留（防 DNS 泄漏），
   加 `--test-type` 让内核不出这条提示，见 decisions U-3。新标签页底部还有一条内核加的署名栏，暂时去不掉。
5. （已处理）新标签页接管提示：改用 `--custom-ntp`，不再弹窗，见 decisions U-1。同时发现并停止了对“受保护偏好”的写入，见 U-2。
6. `subscriptions[].template.basePath` 在接口返回里曾经是空的，生成的路径是对的，没有再查。
7. `internal/core` 和 `internal/probe` 没有单元测试。

## 2026-11-20 实例身份固定 + 默认关闭内核有破绽的五项伪装（SI-1）
- 查明桌面端 `fingerprint-chromium 148.0.7778.215` 在 `--fingerprint` 下的五项伪装（`canvas` 的 `measureText` 算出负宽度、`clientrects` 的 `Range` 与 `Element` 坐标不一致、`gpu` 的 WebGL 与 WebGPU 显卡冲突、`audio` 的 `OfflineAudioContext.sampleRate` 变成小数、`font` 随机屏蔽系统必有字体）存在 C++ 级自相矛盾，导致 Cloudflare Turnstile 反复弹出人机验证。
