# 实现决定与踩过的坑

每条写清：结论、原因、证据（在哪验证的）、影响。新的放在对应小节末尾。
“实测”如果没有另外说明，指无头 Linux（容器里，内核 `--headless=new`）。Windows 的证据只来自 CI 的冒烟测试。

## 内核

### K-1 内核固定在 fingerprint-chromium 148.0.7778.215，不用 150.0.7871.186

- **现象**：150.0.7871.186 开启 `--fingerprint=<种子>` 后，页面一做画布读回（`getImageData`，上游还报告了 `toDataURL`、WebGL `readPixels`），
  渲染进程就崩溃。在无头模式里表现为调试端口上的求值永远不返回，所以一开始被误认为“卡死”。
- **证据**：
  - 本项目实测：`--fingerprint=1000` 下，32×32 红色画布第一次 `getImageData` 必崩；不带 `--fingerprint` 或加 `--disable-spoofing=canvas` 不崩。
    “先读一次纯黑画布再读别的”能让一部分情况不崩，但不可靠（同一套代码有时崩有时不崩），不能当修复手段。
  - 上游 issue #94（Linux，SIGSEGV）、#95、#104（Windows x64，同一版本）描述一致，都说 148.0.7778.215 没有这个问题。
  - 148.0.7778.215 实测：连续 300 次 2D 读回正常；不同种子哈希不同、同种子重启后不变。
- **影响**：内核是 2026 年 6 月的 Chromium 148，比 150 少几个月的安全修复。上游修好后应尽快升级。
- **升级办法**：改 `internal/kernel/fetch.go` 的 `KernelVersion`，跑 `scripts/smoke.mjs`。其中“内核原生：开启指纹后 300 次画布读回不崩溃”
  和“伪装实例里连续 300 次画布读回不崩溃”两项就是为这个问题设的，不过就别升。
- `kernel.Find` 在自动下载目录（`data/kernel/fingerprint-chromium/`）里只认当前固定的版本，换版本后会自动重新下载。

### K-2 内核再次启动时，伴随扩展后台可能起不来；做了自愈

- **现象**：一个实例被强杀多次后，它的资料目录里 Service Worker 注册会卡死：扩展页面能打开，但后台永远不启动，
  `navigator.serviceWorker.getRegistrations()` 都不返回。删掉 `profiles/<id>/Default/Service Worker` 目录后恢复。
- **做法**（`internal/core/launch.go`）：实例运行超过 45 秒而伴随扩展后台一次都没连上核心服务，退出时在资料目录里放标记文件 `.repair-sw`；
  下次启动前看到标记就删掉 `Default/Service Worker`。代价是该实例里网站自己的 Service Worker 要重新注册（下次访问时自动完成）。

## 伴随扩展

### K-3 工具栏图标不经过画布

- 指纹内核会给画布读回加噪声，图标会花；150 版还会崩（K-1）。而 `chrome.action.setIcon({path})` 内部也是画布读回，同样受影响。
- **做法**：国旗和状态图标预先转成 32×32 原始 RGBA 字节，gzip 后放在 `companion/ext/assets/rgba/`（254 个文件，共约 160 KB）。
  后台用 `DecompressionStream` 解开，直接 `new ImageData(...)` 交给 `setIcon({imageData})`，底部 4 像素画成实例颜色。
- 重新生成这些文件：从 `assets/flags/*.png` 缩放到 32×32（保持比例、居中、透明底）导出 RGBA 再 gzip。当时用的是 Pillow，脚本没有入库。

### K-4 伴随扩展的版本号跟着文件内容走

- 内核只在扩展**版本号变化**时才重新安装后台脚本。版本号不变，即使文件改了，资料目录里缓存的还是旧脚本。
- **做法**：`companion.Version()` 返回 `0.1.<a>.<b>`，后两段取自全部扩展文件内容的 SHA-256。启动实例释放扩展副本时把它写进 `manifest.json`。
  源码里的 `manifest.json` 保持 `"version": "0.1.0"` 作为占位，**不要改这一行的写法**（`writeCompanion` 按字符串替换）。

### K-5 停止实例先让伴随扩展关窗口，再结束进程

- 直接结束进程会丢掉最近约 30 秒内写入的 Cookie（内核每 30 秒落盘一次；实测无头 Linux 下 SIGTERM 也不落盘）。
- **做法**（`App.Stop`）：先发 `close` 事件，伴随扩展后台收到后 `chrome.windows.remove` 全部窗口，等 4 秒；没退出再 `taskkill`（Linux 是 SIGTERM），
  8 秒后强杀。
- **已知限制**：无头模式下关掉全部窗口后内核不会自己退出，所以无头测试里总是走到结束进程，刚写入的 Cookie 会丢。
  这一项要在有界面的 Windows 上才算数——CI 的 Windows 冒烟测试用 `--visible` 跑，结果见 `docs/PROGRESS.md`。
- 伴随扩展后台刚被唤醒时从核心服务的当前事件序号开始听，不重放旧事件。否则旧的 `close` 会把刚启动的实例关掉。

### K-6 伴随扩展是纯 JS，没有构建步骤（偏离计划 D4）

- 计划 D4 写的是 TypeScript + 打包。实际界面很小（弹出面板、管理页、新标签页），纯 JS 模块足够，少一条工具链，也更符合“轻”。
- 影响：没有类型检查。CI 里目前也没有对 JS 做静态检查，只有冒烟测试覆盖。要加的话用 `node --check` 逐个文件过一遍即可。
- 扩展 ID 固定为 `doepfdknoapkdegjpopaicigcdnhlifp`，由 `manifest.json` 的 `key` 决定，单元测试会校验 `companion.ID` 与 `key` 一致。

### K-7 界面状态靠长轮询

- 后台对 `/api/events?since=<序号>` 做长轮询，每次返回后刷新图标、角标、悬停文字；另有 30 秒闹钟兜底把后台叫醒；
  任何扩展页面打开时也会发一条 `wake` 消息。

## 界面（Windows 上看到的）

### U-1 新标签页用 `--custom-ntp`，不用扩展清单的 `chrome_url_overrides`

- 用 `chrome_url_overrides` 接管新标签页时，内核第一次打开新标签页会弹“Did you mean to change this page?”，默认按钮是“Change it back”，
  点了它伴随扩展就被停用，整个实例的面板、状态、快捷键全没了。页面底部还会多一条扩展署名栏。（Windows CI 截图里看到的。）
- 这个“已确认”状态存在 `extensions.settings.<扩展ID>.ack_ntp_bubble`，属于受保护偏好，不能从外部预先写入（见 U-2）。
- **做法**：清单里不声明 `chrome_url_overrides`；启动内核时加 `--custom-ntp=chrome-extension://<伴随扩展ID>/newtab.html`
  （ungoogled-chromium 系内核自带的参数，fingerprint-chromium 148 实测支持扩展地址）。
- 代价：换成不支持 `--custom-ntp` 的内核时，新标签页会是内核自带的那个。

### U-2 不要从外部改内核的“受保护偏好”

- Windows 上内核对一批偏好做完整性校验，从外部改了会被判为篡改并**整项重置**，重置记录在偏好文件的 `prefs.tracked_preferences_reset` 里。
  CI 导出的文件显示被重置过的有：`extensions.settings`、`extensions.ui.developer_mode`、`session.restore_on_startup`。
  `extensions.settings` 被重置意味着所有扩展的设置和授权都会丢，所以这条必须遵守。
- 同一类的还有主页、启动页、默认搜索引擎、固定标签页等。Linux 上不校验，所以这个问题只会在 Windows 上出现。
- **做法**：`prepareProfile` 只写普通偏好（实例名、关闭内置密码管理、退出状态、工具栏固定的扩展、WebRTC 策略、语言）。
  恢复标签页靠 `--restore-last-session`；默认搜索靠一个单独的小扩展；解包扩展不需要开发者模式也能加载（Windows CI 实测）。
- 想知道内核把某个设置存在哪：冒烟测试的 `dumpPrefs()` 会把实例的 `Preferences` 和 `Secure Preferences` 拷进截图目录；
  `--click x,y` 可以在截图后点一下屏幕上的按钮，再对比前后两份文件。`ack_ntp_bubble` 这个键名就是这样确认的。

### U-3 启动提示条与新标签页署名栏

- **提示条**（已解决，2026-11-13）：每次启动，第一个标签页上有一条
  “您使用的是不受支持的命令行标记：--host-resolver-rules=MAP * ~NOTFOUND , EXCLUDE 127.0.0.1。稳定性和安全性会有所下降。”
  - 这个参数让内核自己一条 DNS 都不发，是防 DNS 泄漏的兜底，**不能去掉**：走 SOCKS5 时网页请求的域名由代理解析，
    但 WebRTC 解析 STUN / TURN 服务器的域名、DNS 预取这些旁路仍会在本机解析，泄漏检测站正是靠这类旁路看到真实的 DNS 出口。
  - 内核源码（`chrome/browser/ui/startup/infobar_utils.cc`、`bad_flags_prompt.cc`，148.0.7778.215）里，
    `--host-resolver-rules` 在“危险参数”名单的第一条；不出提示只有两条路：
    企业策略 `CommandLineFlagSecurityWarningsEnabled`（要写注册表，会影响本机其他 Chromium，并且菜单里多一句“由贵单位管理”），
    或者启动参数带 `--test-type`。选了后者，只在带 `--host-resolver-rules` 时一起加。
  - `--test-type` 的其他影响（逐个查过同一版源码里用到它的地方）：
    不建任务栏跳转列表；已安装的网页应用不自动更新快捷方式；扩展自己的上下文里多一个 `chrome.test`；
    内核升级后不给扩展补发 `onInstalled(chrome_update)`；带后台页的内置组件扩展不加载
    （这一版非 Google 品牌的构建里本来就没有：Hangouts 组件在 ungoogled 里关了，联网语音合成只有 Google 品牌才有）。
    没有发现网页能观察到的差别；冒烟测试里两个实例的指纹、扩展后台、重启恢复都照常。
  - 同时不再出现的还有：缺少 Google API 密钥、系统过旧、默认浏览器这几种启动提示条（原本也用不上）。
- **新标签页底部的署名栏**（“MaskTab”链接和“Customize Chromium”按钮）：改用 `--custom-ntp` 后仍然在。
  试过在偏好里写 `ntp.footer_visible=false` 和 `ntp.footer.extension_attribution_enabled=false`，没有效果，已经删掉。用户可以在“Customize Chromium”里手动关。

## 代理

### P-1 mihomo 的编排方式

- 每个实例一个本地监听 `in-<实例ID前8位>`，对应一个策略组 `g-<同>`，成员是 `[REJECT, 该实例可选的节点…, DIRECT]`。
  选节点 = 通过 mihomo 的控制接口切换策略组当前项，不重写配置文件（实测切换节点后 `core/config.yaml` 不变）。
- 代理名：通用订阅节点 `s-<订阅8位>-<节点键8位>`；edgetunnel 实例专属节点 `n-<实例8位>`；优选地址 `a-<地址8位>`。
- 节点键 = `sha1(类型|服务器|端口|凭据|host|ws 路径)`。
- 另有一个独立的探测监听，用来测出口 IP，它不受“切断”影响。
- **切断**：代理开着但不可用、出口时区变了需要重启等情况，策略组切到 `REJECT`。任何情况下都不自动切到 `DIRECT`（硬规则 R-1）。
  实测：切断后页面得到 `chrome-error://chromewebdata/`。
- mihomo 意外退出后 1 秒自动重启，并重新选回各实例原来的节点（实测）。

### P-2 edgetunnel 的识别与路径

- 识别规则（2026-11-13 按真实 edgetunnel 的输出改过）：至少 2 个节点；全部是同一种协议（vless 或 trojan）+ ws、凭据相同；
  Host 的种类数 ×2 不超过节点数（通配 Host 按后缀归并）。**路径允许各不相同**：edgetunnel 开“随机路径”后每个节点路径都不一样，
  旧规则要求路径相同，会把它误判成通用订阅。模板优先取带 TLS 的节点。
- 路径改写（实测生成结果）：ProxyIP 出口 `/?proxyip=<值>&ed=2560`；SOCKS5 出口 `/socks5://u:p@1.2.3.4:1080?ed=2560`；没有出口保持 `/?ed=2560`。
- 优选 IP“同出口”模式：直接把出口地址当作连接的服务器。出口当入口不可用时显示“出口探测失败”并切断，不回落。
- 验证方式：本地用 wrangler 跑真实的 edgetunnel `_worker.js`（2026-11-10 版），前面放一个 TLS 终结，订阅走它自己的 `/sub`。
  默认配置、0-RTT、随机路径、ECH、三者同开、经 subconverter 的 Clash YAML 都测过。用户自己的线上订阅仍然没有测过（V5）。

### P-4 ECH

- edgetunnel 链接里的写法是 `ech=<查询名>+<DoH 地址>`（如 `cloudflare-ech.com+https://dns.alidns.com/dns-query`）。
  旧代码只生成 `ech-opts: {enable: true}`，mihomo 就去查节点 SNI 自己的 HTTPS 记录，查不到，报
  `resolve ECH config error: no ECH config found in DNS records`，表现为**全部节点测速超时、实例打不开**。
- 现在：`ech-opts` 带上 `query-server-name`；长 Base64 当作 `config`；没转义的 `+`（会被解析成空格）也认。
- 只要有出站用了 ECH，配置里就加 `dns` 段：默认用系统 DNS，只把 ECH 查询名用 `nameserver-policy` 指到国内可达的 DoH
  （alidns、doh.pub）。实测 mihomo 1.19.34 能据此取到 Cloudflare 的 ECH 配置。
- **自动回退**：一轮测速后如果全部节点都不通且原因是 ECH，把该订阅标记为“不使用 ECH”（`echOff`）再测一遍。
  Cloudflare 上的服务端同时接受不带 ECH 的连接，所以回退后能用。面板“更多”里可以手动开关。
- 本地验证的限度：本地的 TLS 终结不支持 ECH，所以“带 ECH 连通”演示不了；验证到的是 ECH 配置能取到、以及回退后连通。

### P-5 测速与节点列表

- **全部订阅的全部节点都写进 mihomo 配置**（edgetunnel 每个优选 IP 一条不带出口参数的出站）。旧做法只写“正在运行的实例用到的节点”，
  结果是没开伪装实例时通用订阅的节点全部测成超时。
- 另开 4 条**测速通道**（`in-scan<i>` + `g-scan<i>`），测出口 IP 时把通道切到要测的节点再发真实请求。
  延迟用 mihomo 的延迟接口并发测；出口 IP 经测速通道访问 `checkip.amazonaws.com` 等，再查归属地。结果存 `state/scan.json`，12 小时内不重复查出口。
- **失败原因**取自 mihomo 日志里该策略组最近一次拨号错误，翻译成一句话（连接被拒绝 / 连接超时 / 握手被中断 / 证书校验失败 / 服务端拒绝 / ECH…）。
- 配置重载会把所有策略组重置。用一个重载计数识别“测试期间发生过重载”，发生过就重测一次，避免把节点误判成不通。
- **自动选节点**（`proxy.auto`，新实例默认开）：启动时或探测失败时，当前节点可用就不动（出口稳定优先于速度）；不可用才测一遍并换成延迟最低的，
  最多换两次。手动点选某个节点会关闭自动。自动只在“代理开着”的前提下换节点，永远不会切到直连（R-1 不变）。
- 界面上一张列表：地址、备注 · Host、出口 IP 与归属地、延迟。edgetunnel 的“节点”就是优选 IP；ProxyIP、Host、自定义地址、ECH 开关收在“更多”里。

### P-6 入口、反代与"出口地区"（2026-11-13，依据真实订阅实测）

实测结论（需求方的 edgetunnel 订阅，20 条链接只有地址不同）：

- 普通网站从 Worker 所在的 Cloudflare 机房出去（`104.28.x`），**每次请求 IP 都可能变**，入口地址只决定机房在哪个国家。
- Cloudflare 上的网站从反代（ProxyIP）自己的固定地址出去，与入口无关；不指定时用服务端默认值，国家可能与入口不同。
- 所以一条线路固有两个出口。只有 SOCKS5 / HTTP 全局出口或"通用 ProxyIP"能让所有网站看到同一个 IP。

据此的做法：

- 入口有三个来源：订阅里的地址、自己加的地址、反代列表里每个解析出的 IP（它们大多也能当入口）。
- 反代候选有两个来源：反代列表，以及入口里不属于 Cloudflare 网段的地址（标"入口"）。`主机:端口` 相同即同一台机器。
- 测速分三步：延迟 → 每个入口的两路出口 → 经一条可用入口测每个反代的出口。结果存 `state/scan.json`。（edgetunnel 订阅已改为直接探测，见 P-7。）
- 面板的主控件是**出口地区**：在该地区里选最快的可用入口，再配一个同国家的反代。
  选不出时线路保持不变并说明原因，不退到别的地区。手动选入口或反代即关闭自动。
- 订阅每次返回的地址都不同：新结果里没有的地址标"旧"，在用的或还通的保留（每个出口国家最多 6 个），其余删掉。
- **延迟口径**：配置开 `unified-delay`，显示的是连接建好之后的一次往返。
  之前显示的是首次请求耗时（TCP + TLS + WebSocket 握手再加目标站 TLS，约 5 到 6 个往返），与别处的 tcping 数字差几倍。
- 计划里的"优选 IP 同出口 / 自选"药丸开关取消：反代 IP 直接出现在入口列表里，效果相同，少一个概念。

### P-7 直接探测、优选与反代的识别、测下载（2026-11-13，参照 edgetunnel 面板的"在线优选"）

第三轮反馈：国旗不显示、"1 / 58 可用"、反代列表不全、测速慢且只测了入口。原因是同一个：
出口信息全靠"经代理内核一条一条建隧道"去测，慢，而且隧道一旦建不起来，国旗、延迟、出口就全是空的。

edgetunnel 的"在线优选"是这样做的：浏览器直接连被测地址，请求一个返回 `ip / country / colo` 的小接口；
返回的 `ip` 是自己的公网 IP，说明连的是 Cloudflare 官方 IP（优选）；否则是反代，`country` 是反代机器所在国家。
测下载是 `__down?bytes=…`，流式读，每 250 毫秒报一次速率。

据此的做法（`internal/cfprobe`、`internal/core/fastscan.go`）：

- edgetunnel 订阅的地址**不经代理内核，本机直接连**，请求 Cloudflare 自带的 `/cdn-cgi/trace`。一次请求得到：
  通不通、TCP 握手耗时、一次往返的延迟、落在哪个机房（= 普通网站的出口国家）、Cloudflare 看到的来源 IP（= 把它当反代用时的出口）。
  32 路并发，单个 4 秒超时，结果随测随显示；没有运行中的实例、代理内核没起来也能测。
- **优选还是反代自动识别**：地址在 Cloudflare 网段内，或 trace 返回的来源 IP 等于本机公网 IP → 优选（只能当入口）；
  否则 → 反代（入口和反代都能当）。导入时不用区分。
- 每个 `地址:端口` 写两条记录：作为入口的、作为反代的。所以反代列表 = 所有识别为反代的地址，不再依赖"经某条入口去测"。
- 探测用的站点名：`/cdn-cgi/trace` 由 Cloudflare 自己应答，用哪个站点名问都一样。
  `workers.dev` / `pages.dev` 的名字在部分网络里一出现在握手里就被掐断（实际连接靠 ECH 藏名字，探测不走 ECH），
  这两类直接用 `speed.cloudflare.com`；自定义域名先用自己，握手或应答不对再换它试一次。
- **测下载**：经被测地址从 `speed.cloudflare.com/__down` 下载，最多 6 秒，报峰值（最好的连续 1 秒）和平均值，测的过程中实时更新。
  一次只测一个（并发会互相抢带宽）；可以单测一行，也可以批量测延迟最低的 8 个。
  端点对单次下载大小有上限（实测 1 亿字节返回 403，5000 万可以），从 5000 万、2000 万、1000 万依次试。
- SOCKS5 / HTTP 全局出口不是 Cloudflare 的地址，仍经代理内核测。通用订阅（非 edgetunnel）保持原来的测法。
- 导入放宽：IP、`IP:端口`、域名、`#备注`、空白或逗号分隔、测速工具导出的 CSV 都认，不是地址的列自动丢掉；
  也可以贴一个列表网址（`https://…/ip.txt`），导入时拉取一次。网段（CIDR）不支持。一次最多 500 个地址。
- 限制：直接探测量的是"本机到这个地址"，本机如果开着别的全局代理，量到的是那个代理。延迟和速度都在本机测，换个网络结果会变。

面板随之重排（`companion/ext/popup.*`）：

- 主界面只有四块：实例头、当前两路出口、伪装设备 / 时区 / 语言一行（点开是指纹设置）、线路三行（地区 / 入口 / 反代）。
- 点任一行进入占满面板的列表：国旗筛选、优选 / 反代筛选、按延迟或下载排序、每行可单独测下载。
- 文字尽量换成图标，完整说明放在悬停提示里。国旗以实测为准；还没测到时按备注里的国家猜一个，显示得淡一些。
- 打开面板时，上次探测超过 10 分钟就自动重测一遍。

### P-8 出口 / 入口各自的自动与手动、线路、IP 类型与纯净度（2026-11-13，面板第五版）

**两个开关。** 出口和入口各有一个"自动"开关（`exitMode` / `entryMode`，空 = 自动）。只有这两个字段改模式；
在列表里点一行由面板显式带上 `manual`，选国家带上 `exitMode: auto`。旧的 `auto` 字段只为兼容保留。

- 出口自动：只认国家。当前反代还通、还在这个国家就不动；否则按"用户自己加的在前、没被别的实例占用的在前、延迟低的在前"换一个。
  这个国家没有反代时，退回去找出口在这个国家的入口。**绝不悄悄换国家**：找不到就给 `noexit:<国家>` 提示，线路保持原样。
  没选国家：用最快的入口，反代配成和入口同国。
- 出口手动：钉死，不换。Cloudflare 那一路不通时只提示。
- 入口自动：反代那台机器自己能当入口就用它；不行就用延迟最低的，同国优先，没有再全局。
- 入口手动：钉死。
- 通用订阅（非 edgetunnel）节点就是出口，只有一个开关。
- "换一个"（`POST /api/instances/{id}/next`）：在当前国家里按上面的顺序轮着换，到头回到第一个。出口手动时拒绝。

**自动换线**（`refreshTry`，最多两次）：整条线不通 → 换入口（仅入口自动）；普通网站通、Cloudflare 网站不通 → 换同国的下一个反代（仅出口自动）。
换成功后给 `switched` 提示，面板上说一句"已自动换线路"。

**线路（profile）。** 一个 edgetunnel 订阅地址里可以有几个 Host、几种传输（ws / xhttp）。每个 Host + 传输是一条线路，实例记自己用哪一条（`proxy.profile`）。
同一后缀下超过四个 Host 的（泛域名）并成一条 `*.后缀`，里面的 Host 按实例平分。新实例只在和第一条线路同传输的线路里分配，所以 xhttp 要手动选。
测速和直接探测用第一条线路。同一地址同一 Host 的 ws 和 xhttp 是两个节点（节点 key 里带传输，ws 不带，旧 key 不变）。
xhttp 只验证到 `mihomo -t` 认配置，**没有实连过**。

**IP 类型与纯净度。** 来源 `ip.net.coffee` 的 `trust_score`（0–100，越高越干净）和住宅 / 机房 / 移动标记；查不到类型时用 ip-api 的 `hosting` / `mobile` 补。
按 IP 缓存 7 天（`state/ipq.json`），失败的 10 分钟后重试，6 路并发，一轮最多 400 个。有健康的实例时经它的探测端口去查，否则直连。
查不到就不显示，不编数字；保留地址返回的 0 分丢掉。这会把出口 IP 发给第三方，设置里可以关（`ipqOff`），关掉后以前查到的也不显示。

**面板。** 宽 320 px，样式全部内联在 `popup.html`。订阅一栏：线路条数、当前线路（点开切换）、加号再加一个订阅地址（名字留空时用地址的域名）。
出口 / 入口各一张小卡：名称 + 自动开关，下面是当前值；手动时点进占满面板的列表（两行一条：地址 + 延迟，类型 + 纯净度）。

### P-3 时区

- 默认跟随出口：启动前先探测两路出口（`https://www.cloudflare.com/cdn-cgi/trace` 和 `https://checkip.amazonaws.com`），按国家取时区和语言，
  作为 `--timezone`、`--lang` 传给内核。两路都探测失败且时区是“自动”时拒绝启动，并提示可以改成固定时区后强行启动。
- 运行中出口时区变了：切断，并在界面提示需要重启该实例。
- 实测：页面与 Worker 里的时区、`Intl`、时间偏移都跟着变。

## 组件下载与安装

### D-1 下载途径

- 两个组件（浏览器内核约 190 MB、mihomo 约 22 MB）都在 GitHub 上，国内直连经常超时。旧代码只有一条直连、整体 10 分钟超时、不能续传。
- 现在依次尝试：直连 → 本机已有的代理（环境变量、Windows 系统代理、常见端口 7890 / 7897 / 10809 / 10808 等，先探测确实是代理）→ GitHub 镜像
  （设置里的镜像前缀优先，其后是内置的几个）。订阅拉取用同一套途径，但不走镜像。
- 断点续传（`.part` 文件，换途径接着下）；25 秒没有数据算卡住；第一轮里平均不到 30 KB/s 的途径会被放弃，第二轮不再嫌慢；
  返回网页的途径直接跳过。
- 镜像不可信，所以**下载完一律校验内置的 SHA-256**（取自上游发布页的 digest），不符就丢弃换下一个途径。换固定版本时要同时改 `internal/kernel/fetch.go` 里的校验值。
- 需要下载浏览器内核时，用系统默认浏览器打开本机的进度页 `http://127.0.0.1:<端口>/setup#<令牌>`（令牌在 `#` 后，不会发给任何服务器）。
  页面显示进度、速度、当前途径、失败原因、重试，以及手动安装的位置。
- 代理内核出问题（下载失败、被安全软件拦截）不再挡住浏览器：普通窗口照常能开，面板上显示原因和重试。

### D-2 安装程序

- NSIS 脚本 `installer/masktab.nsi`，一份脚本出两个包：普通包（只有 `masktab.exe`）和完整包（加浏览器内核与 mihomo）。
- 装到 `%LOCALAPPDATA%\Programs\MaskTab`，不要管理员权限。数据目录仍是程序目录下的 `data`（与解压版一致，所以解压版用户选原目录安装即可接上）。
- “只更新变了的部分”的规则：`masktab.exe` 总是替换；`mihomo.exe` 靠 `mihomo-<版本>.ver` 标记，版本相同跳过；
  内核目录 `kernel\fingerprint-chromium\<版本>\installed.ok` 存在（或 `data\kernel` 里已有这个版本）就跳过，版本变了才装并删除旧版本；`data` 从不碰。
- 升级前调用 `masktab.exe -quit` 让运行中的 MaskTab 自己关窗口退出，等文件解除占用；20 次不成再强制结束。
- 核心服务找组件的顺序没变：程序目录 → `data\core`、`data\kernel` → 设置里的内核路径 → `程序目录\kernel`。所以安装程序只要不动 `data`，以前下载的也继续用。
- CI 在 Windows 机器上构建两个包，把完整包静默安装后**对装好的那一份跑冒烟测试**，再验证：运行中升级、完整包覆盖安装跳过内核、卸载保留数据。
  两个包发布到 Releases。

### D-3 两端同步发布（2026-11-14，需求方：“合并吧，之后一起更新同步发布”）

- 安卓分支 `demo/android` 并入 `main`，以后两端都在 `main` 上改，不再分开。
- 一次推送到 `main` = 一个版本号 `0.1.<CI 运行序号>` = 一个 Release，里面同时有 `MaskTab-Setup-Full.exe`、`MaskTab-Setup.exe`、`MaskTab-android-arm64-v8a.apk`。
- 做法：`ci.yml` 在 `main` 上调用 `android.yml`（`workflow_call`），再由单独的 `release` 任务等单元测试、Windows、Linux 冒烟、安卓构建与模拟器冒烟**全部通过**后一起发布；任何一项不过就整个不发，不会出现只发了一端的版本。
- 安卓版本号（`versionCode` / `versionName`）取 `GITHUB_RUN_NUMBER`；被 `ci.yml` 调用时就是 CI 的运行序号，所以和电脑版一致，并且比之前的试用版（`android-v0.1.9 / 13 / 14`，按安卓工作流自己的序号）大，可以覆盖安装。
- 代价：只改电脑端的代码也要等安卓模拟器测完（约 15 分钟）才发版；Release 多 128 MB 的 APK。
- 其它分支：`ci.yml` 照常跑电脑端测试、不发版；`android.yml` 在安卓相关文件有变化时自己跑、只出产物。
- 之前的三个安卓试用版（prerelease）保留，不再新增。

## 核心服务

### C-1 本地接口的访问控制

- 只监听 `127.0.0.1` 的随机端口；必须带 `X-MaskTab-Token`；`Host` 必须是 `127.0.0.1`；如果带 `Origin`，必须是伴随扩展的来源。
- 端口和令牌写在 `data/state/running.lock`，每个实例的伴随扩展副本里有一份 `config.json`。
- 实测：无令牌 401，外部来源 403，错误的 Host 403。

### C-2 崩溃恢复

- 核心服务把各实例内核的进程号写在 `state/runtime.json`，mihomo 的写在 `core/mihomo.pid`。
- 启动时如果发现上次遗留的进程还在（并且确认是自己的内核 / mihomo），先结束它们，再按恢复列表重新启动上次开着的实例；
  内核带 `--restore-last-session`，标签页会回来。
- 为什么必须清理：遗留的内核进程会让新启动的内核把窗口交给旧进程后立刻退出；遗留的 mihomo 会占着端口。

### C-3 入口行为

- 第二次运行 `masktab` 时发现已有核心服务，就请求它打开普通窗口（`POST /api/open`）后退出。
- 没有托盘图标（未做）。全部窗口关闭 6 秒后核心服务自动退出，除非带 `--keep` 或 `--no-open`。
- #0 是普通窗口，不开指纹，代理默认关闭。实例编号只增不复用。

### C-4 删除实例

- 主进程退出后子进程还会再写几个文件，Windows 上文件可能仍被占用，所以删除资料目录要循环删到确实不存在为止（最多约 5 秒）。
- 停止、重启、删除这几个接口都是立即返回、后台执行；调用方要看 `/api/state` 里的 `rt.running` 才知道做完没有。

## 测试办法

- 没有显示器时用无头模式，见 `AGENTS.md`。内存 2 GB 的机器上同时最多开一两个无头实例，否则调试端口会没有响应。
- 假节点服务端：再起一个 mihomo，配置里放 ss 入站（两个端口、不同密码）和 vless+ws+TLS 入站（自签证书，订阅链接里带 `allowInsecure=1`），
  订阅文件用 `python3 -m http.server` 提供。mihomo 不接受没有证书的 vless 入站。
- 假 edgetunnel：`go run ./scripts/fakeet -port 8443 -colo NRT -loc JP [-lag 30]`，一个端口一个进程（自签证书，订阅链接带 `allowInsecure=1`，server 写 `127.0.0.1`）。
  它回 `/cdn-cgi/trace`（直接探测靠这个），转发 VLESS over WebSocket，目标是 Cloudflare 的地址时改连路径里的 `proxyip`，所以两路出口和真的一样。
  杀掉某个端口的进程 = 这个入口坏了；入口地址派生出来的"反代"是假的，选中它 = 反代坏了。自动换线就是这么测的。
- 面板截图：用调试端口新开 `chrome-extension://<ID>/popup.html`，`Emulation.setDeviceMetricsOverride` 设成 320 宽再截。
- 调试扩展后台：用调试端口附着到 `service_worker` 目标求值。不要从扩展页面 `import('./background.js')`，那会启动长轮询、永远不返回。
- `pkill -f "模式"` 可能把调用它的 shell 也杀掉，模式里用 `[x]` 写法，例如 `pkill -f "[h]ttp.server 28080"`。

### N-1 出站绑定物理网卡，绕过本机 TUN（2026-11-14）

- 问题：浏览器只走本地 mihomo，但 mihomo 的出站按系统路由表走；本机开 TUN 后会被二次代理，出口 IP、延迟、DNS 都变。
- 做法：自动识别物理网卡（排除虚拟网卡名、无 MAC、TUN 地址段 198.18.0.0/15 等），mihomo 全局 `interface-name` 绑定；
  绑定时 DNS 模块打开，用 223.5.5.5 / 119.29.29.29 / DoH（按 IP），不用 `system`（TUN 的 fake-ip 会把系统 DNS 劫持成 198.18.x）。
  核心服务自己的直连请求用 `netx.BindDialer`（Windows IP_UNICAST_IF、Linux SO_BINDTODEVICE、macOS IP_BOUND_IF）。
- 设置 `bindIface`：空 = 自动（默认）；`off` = 不绑定；其它 = 指定网卡名。识别失败时不绑定（行为与以前一样）并写日志。
- 风险：识别错网卡会导致全部不通（R-1 下是切断，不会泄漏）；遇到时在设置里关掉或指定网卡名。没在 Windows + TUN 上实测。
- 回退：设置里选“关”，或删掉 `Input.Interface` 的赋值。

### M-1 密码库与自动填写（2026-11-14）

- 整个库一份文件 `config/vault.bin`：Windows 用 DPAPI（当前用户），其他系统用同目录 0600 的随机密钥 + AES-GCM。换电脑 / 换系统用户就解不开，此时不覆盖原文件，界面报错。
- 每条记录带所属实例（F-PWD-1）。填充只在站点完全匹配时（协议 + 主机 + 端口）；不进内嵌框架；站点由后台取自发送方真实地址，不信内容脚本说的。
- 自动填写只填不提交（需求方默认）。本实例恰有一条记录才自动填；多条或只有别的实例的记录，聚焦时弹选择。
- 批量导入的邮箱记成站点 `*` 的账号：只给本实例用，排在站点精确匹配的记录之后。
- 默认密码全局一个，存在同一个加密库里；`/api/state` 只给“有没有”，不给值。
- Cookie 只上报“基础域名 + 条数”，内容不离开实例。

### M-2 工具栏头像（2026-11-14）

- 原生个人资料按钮和菜单是内核的 C++ 界面，不打补丁改不了。做法：伴随扩展按钮（已固定在工具栏）图标画成实例色圆 + 首字母 + 国旗角标，点开先显示实例菜单；节点面板变成菜单里的一项。
- 字形表 `assets/rgba/_glyphs.gz` 由 `scripts/glyphs/gen.py` 生成（0–9、A–Z，18×18 透明度），后台逐像素拼图，不经画布（K-3）。
- 断流 / 出错时仍显示原来的状态图标，延迟仍在角标上。
- **2026-11-13 改（需求方：两位数编号只显示一位；延迟角标把国旗盖住了）**：
  - 头像上的字：电脑上是名字里的第一个字母；名字以数字开头就取开头那串数字（最多 3 位）；没有可用的字就写整个实例编号。手机上一律写编号。
    两位 / 三位时字缩小（网页里的头像加 `l2` / `l3` 类；工具栏图标按字数缩放字形）。算法在 `common.js` 的 `letterOf`，两端共用。
  - 工具栏图标（`icon.js`，纯函数，逐像素）：实例色圆 + 白字；国旗 17×12 带 1 像素白边放右下角，**上面不再压任何东西**。
    延迟不再用浏览器的数字角标（角标是浏览器画的，三位数会把国旗整个盖住），改成左下角一个色点：绿 < 200 ms、橙 < 500 ms、其余红。
    数值在悬停提示和面板里。测速失败仍用 `×` 角标；断流 `✕`、出错 `!`、需重启 `↻` 不变。

### M-3 标记网站：录入登录（2026-11-14，需求方：“先把功能跑通，之后优化”）

- 是什么：自动识别认不出的登录页，或者想明确记下来的网站，用户点“录入”后照常登录一次，程序记下两样东西：
  - **规则**（全部实例共用）：这个网站哪个框填邮箱 / 账号 / 手机号、哪个框填密码。只有选择器，没有账号内容。
  - **账号**（只属于当前实例）：这次输入的用户名和密码，进密码库。
- 入口两个：聚焦像登录框的输入框时旁边出现“录入”小按钮（只在这个网站没有规则、本实例也没有它的账号时出现）；实例菜单里的“录入登录”（任何时候都能点，用来重录）。
- 结束条件 = 登录成功，判断方法：点过登录之后登录框不见了。
  - 录到了密码：密码框不见超过 1.2 秒就算成功（后面的两步验证页不用等）。
  - 只录到账号（短信登录、两步登录的第一步）：账号框也不见、点登录超过 6 秒、页面加载超过 3 秒才算，免得把“第一步 → 第二步”的切换当成成功。
  - 点了登录 12 秒登录框还在：当作没登上，接着录；用户重输就覆盖。
  - 录入条上有“完成”（立刻保存已录到的）和“✕”（取消；这个标签页这个网站 10 分钟内不再自动录入）。10 分钟没完成自动放弃。
- 认框：只认用户亲手输入的（`isTrusted`），点登录那一刻再把粘贴 / 自动填好的读一遍。类型按内容猜：含 `@` 是邮箱，6–15 位数字且像手机号是手机号，其余是账号；验证码框（名字像 code / otp / 验证码，或很短的纯数字框）不记；密码提交之后才出现的新框不当成账号。
- 选择器：稳定的 `id` → `name` → 密码框类型 → `autocomplete` → `placeholder` → 输入框类型；带长数字 / 哈希的 `id`、`name` 视为不稳定，跳过。同一选择器命中多个时记下第几个。
- 共用规则怎么生效：别的实例打开有规则的网站——本实例有这个网站的账号，按规则找框填；没有，自动进入录入，登录一次就记住（自动录入不改写规则，只有手动录入才写）。
- 跨页面的登录流程：录到一半的内容（含密码）暂存在扩展后台的内存里，按“标签页 + 主域名”，10 分钟，换页后接着录；不落盘，不进网页能读到的存储。
- 存储：规则放在密码库文件里（`rules`），接口 `PUT /api/vault/rule`、`DELETE /api/vault/rule?site=`，`GET /api/vault/match` 的回复里带 `rule`；状态里 `vault.rules` 只有站点、类型、由谁录入，不带选择器。桌面（Go）和安卓（Kotlin）各一份，形状相同。
- 从菜单触发：桌面由弹出面板直接给当前标签页发消息；安卓由后台转给这个实例正显示着的网页（内容脚本在页面显示 / 隐藏时报一声），转不到就记下来，2 分钟内下一个显示出来的网页接手。
- 录入条默认在页面顶部中间，会挡住输入框 / 按钮时挪到底部；条本身不拦点击。
- 测试：`scripts/rec-test.mjs`（Playwright，Chromium 和 Firefox 各跑一遍，后台用假的顶替）；Go 接口测试 `TestRuleRoutes`、`TestRules`。
- 已知不足（之后优化）：登录按钮在内嵌框架里的网站不支持（内容脚本只在顶层页面工作）；用 CSS 把普通文本框伪装成密码框的网站，密码会被当成账号；规则目前只用来找框，`path`（哪一页）记了没用上；“怎么用？”的说明在手机上是悬停提示，看不到。


### M-4 录入登录闭环：存到哪、谁来存、提示与站点图标（2026-11-13）

需求方反馈（电脑版 0.1.43）：录入能走完，但再打开登录页不自动填，账号管理里也没有这个网站；密码像是内核自带的密码管理填的。

- **查到的原因**（用 0.1.43 的逻辑在仿真网站上复现）：保存是在网页里、登录成功之后才发的，用的是“当时所在页面”的地址。
  - 登录页在 `login.x.com`、登录后跳到 `www.x.com`：账号和规则都记在了 `www.x.com` 名下，登录页自己名下什么都没有。
  - 登录页在另一个站（单点登录）：跳走时页面已经没了，什么都没存下。
- **谁来存**：改成后台存。网页只发一条消息（`vault:remember` 或 `vault:rec-finish`），后台一次办完“存账号 + 存规则 + 清暂存”，
  所以提交后立刻跳转也丢不了。录入中的内容按标签页暂存（10 分钟，不落盘）。录入已提交且有密码时关掉标签页（登录弹窗）也照样保存。
- **存到哪**：每个输入框由后台盖上“发送方的真实地址”，账号和规则都记在**输入框所在的网站**名下，不是登录后落脚的网站。
- **匹配**：`www.` 和裸域名算同一个站。同一实例里兄弟子域名的账号（按简化的主域名算；`github.io` 这类公共后缀不算；协议要相同）
  只进选择列表、带上来源主机名，**不自动填**（M-1 的“站点完全匹配才自动填”不变）。
- **登录页提示**：页面像登录页、这个网站没有规则、本实例也没有它的账号时，右上角出一张小卡片“录入这个网站的登录？”，点“录入”直接开始；
  点“不用”30 天内这个网站不再问（按实例 + 主机名记在扩展本地存储里），菜单里的“录入登录”仍然可用。原来输入框旁边的小按钮保留。
- **站点图标**：记住账号后，内容脚本顺手取一次网页图标（不带登录状态，只收图片，不超过 48 KB）交给核心服务，和密码库存在一起；
  只为“密码库里有账号的主机名”存。界面只读本机接口 `GET /api/vault/icons`，不向外发请求。显示顺序：内置品牌图标 → 存下的网页图标 → 字母块。
- **内核自带的密码管理**：偏好文件里本来就关了（F-PWD）；这次伴随扩展再用 `chrome.privacy` 关一次（扩展设的值压过设置页）。
  已经存在内核自己密码库里的旧记录不删（那是用户的数据），需要用户自己在 `chrome://password-manager` 里清。
- **代码位置**：后台逻辑两端共用 `companion/ext/vaultmsg.js`（`MTVault(env)`），两端后台只提供 `env`：怎么发请求、标签页属于哪个实例、暂存放哪
  （电脑 `chrome.storage.session`，手机内存）。
- **测试**：`scripts/rec-test.mjs`（真 `autofill.js` + 真 `vaultmsg.js` + 真核心服务，网站是仿真的，Chromium / Firefox 各 38 项）；
  `scripts/ext-e2e.mjs`（把伴随扩展真的装进 Chromium 走一遍，16 项）。两个都进了 CI。

### D-4 两端同一个核心服务、同一份面板代码（2026-11-14，需求方：“把电脑端和手机端功能尽可能统一一致，之后修改任何一个功能双端都会同步修改”）

**以前**：手机端的实例、订阅、选线、密码库是用 Kotlin 另写的一套（`Store.kt` `Mihomo.kt` `Vault.kt` `Identity.kt`），界面也另画（`android/ext/main.js` 里的节点页、订阅页、设置页）。
电脑上有的功能（edgetunnel 识别、出口 ProxyIP / 入口优选 IP、自动选线、多订阅、地址库、测速、纯净度…）手机上都没有，改一个功能要改两遍。

**现在**：
1. **核心服务只有一份**。APK 里带着电脑版那个程序（`cmd/masktab`，编成 `jniLibs/<abi>/libmasktab.so`），app 把它当子进程启动：`-host android`（“宿主模式”）。
   宿主模式下它只少做一件事——不启动浏览器进程（浏览器是 GeckoView，由 app 管）；实例、订阅、选线、mihomo 配置、出口探测、时区语言、密码库、录入规则全是电脑版的原代码。
   Kotlin 那四个文件删了。`Bridge.kt` 变成转发：页面的请求原样转给核心服务（同样的路径、参数、返回值）。
2. **界面共用到文件**。节点面板 = `companion/ext/panel.js` + `panel.css`（电脑放进工具栏弹窗，手机放进“节点与出口”页）；
   订阅与出口、设置 = `pages.js`；实例菜单、实例管理、自动填写本来就是共用的。安卓构建时把这些文件拷进 APK，仓库里只有一份。
3. **差别用“内核能力”表达，不写两份**。核心服务在状态里报 `kernel.caps`（`platform` 能否换系统 / 浏览器、`spoof` 能否逐项开关伪装、`extLib` 有没有扩展库、`live` 改指纹是否免重启）和 `host`；
   共用的页面按这个决定显示哪几项。手机上没有的只有内核做不到的那几样（见 docs/android.md“两端还剩的差别”）。
4. **一起验证**。CI 里同一份核心服务状态分别画电脑版弹窗和手机页面，面板文字必须一样（`preview-pages.mjs`）；`go test` 两端共用；模拟器冒烟测试里核心服务真的在安卓上跑。

**宿主模式的规矩**（`internal/core/host.go`）：
- 实例没有“打不开”：浏览器一直在，没有可用出口时实例照样算运行着，只是断流（mihomo 里是 REJECT），原因显示在面板上；选好节点后自己恢复。**任何情况下不回落直连。**
- 实例端口固定为 21000 + 编号（被占用才换），内置扩展按它分流。
- 改时区 / 语言 / 指纹不用重启（`caps.live`）：页面内的伪装脚本每次加载网页时向 app 要最新的参数。
- 密码库的密钥由 app 从 Android Keystore 解出来，经环境变量 `MASKTAB_VAULT_KEY` 交给核心服务；库文件离开这台手机解不开。
- app 退出（标准输入关闭）核心服务跟着退出，连同 mihomo。
- 旧数据（0.1.41 及以前的 `files/state.json`、`vault.bin`）第一次启动时搬进核心服务（`POST /api/host/import`）：实例 id、编号、名称、颜色、指纹种子、固定的时区语言、账号密码、录入规则原样保留；
  订阅重新拉一次，原来钉着的节点按名字对上，对不上的保持断流；订阅当时拉不下来也不改成直连。旧文件改名 `.old` 留底。

**代价**：APK 每个架构大约多 10 MB（Go 程序）；手机上多一个常驻子进程。
**放弃的做法**：把电脑版的逻辑用 Kotlin 再写一遍（两份代码永远对不齐）；把内核换成 xray（见上一轮的答复）。

## 安卓版（2026-11-14，起初在分支 demo/android，已并入 main，见 D-3；详见 docs/android.md）

### A-1 安卓用 GeckoView，不用计划第 9 章的系统 WebView（偏离计划 D14）

- **结论**：安卓版内核用 Mozilla 的 GeckoView（固定 160.0.20261104181552），需求方 2026-11-14 拍板。
- **原因**：
  - 计划里的系统 WebView 方案本身就把“Google 登录可能被拦”（VA2）列为风险，备选正是 GeckoView。
  - 多实例隔离：GeckoView 有 `contextId` 容器，一个进程里多个实例同时存活、各自 Cookie / 存储隔离；WebView 要靠“进程槽位 + `setDataDirectorySuffix`”，每个实例一个进程、数量有上限、切换要重启进程（VA1 未验证）。
  - 每实例代理：WebView 的 `ProxyController` 是整个进程一个代理；GeckoView 里内置扩展的 `proxy.onRequest` 可以按标签页分流，一个进程里多个实例走不同出口。
  - 扩展：GeckoView 支持 WebExtension，桌面伴随扩展的 `autofill.js`、`menu.js`、`instances.js` 能复用；用户还能从 AMO 装扩展（计划里手机端原本“不做扩展”）。
  - 内核版本由 app 自带、跟着 Firefox 正式版走，不受手机系统 WebView 版本影响。
- **代价**：APK 大（每个架构约 80 MB 的 libxul）；网站看到的是安卓火狐（不伪装 Chrome）；只能装 AMO 签名的火狐扩展；页面指纹在扩展层做，弱于桌面内核级；Service Worker 第一版关闭（A-3）。
- **回退**：WebView 方案仍可按计划第 9 章做，`android/` 下的 mihomo、密码库、扩展页面大部分可复用，只有 `Core.kt`（会话、容器、代理分流）要重写。

### A-2 mihomo 的 proxy-providers 必须写 `proxy: DIRECT`

- 沙箱实测（mihomo v1.19.34 Linux arm64）：provider 不写 `proxy` 时，拉订阅这个请求也走规则匹配，被兜底的 `MATCH,REJECT` 拒掉，日志是 `EOF`。写 `proxy: DIRECT` 后正常拉取。
- 订阅里的节点不在 `/proxies/<名>` 下，单测延迟要用 `/providers/proxies/sub/<名>/healthcheck`。

### A-3 关闭 Service Worker

- Service Worker 发出的请求 `tabId = -1`，而 GeckoView 里 `details.cookieStoreId` 不准（bug 1948114），分不出属于哪个实例。为了守住“认不出就拒绝、绝不直连”，第一版用偏好 `dom.serviceWorkers.enabled: false` 关掉。
- 影响：离线、推送等依赖 Service Worker 的网站功能没有。以后 GeckoView 修好 cookieStoreId 后可以打开，改 `Core.writeGeckoConfig` 与 `ext/background.js` 的 `proxy.onRequest`。

### A-4 标签页 → 实例的识别

- CI 模拟器里看到：GeckoView 容器标签页的 cookieStoreId 就是 `firefox-container-` + contextId，例如 `firefox-container-mt-a14fd374`。
  所以后台直接从 cookieStoreId 认实例（`tabs.get(tabId).cookieStoreId`，不用 `details.cookieStoreId`，见 bug 1948114）。
- 兜底：app 开的每个标签先进扩展自己的引导页 `newtab.html#inst=<id>&go=<网址>` 登记，再跳网址（扩展页不走代理，第一跳不漏）；
  网页内容脚本的原生消息由会话自己的 MessageDelegate 接收（app 按会话知道实例），再告诉后台。网页伪造不了这两条。
- ~~指纹脚本按容器 `contentScripts.register({cookieStoreId})` 同步注入。~~ **这条是错的，已废弃，见 A-7**：调用被接受不等于按容器生效。
- GeckoView 的坑：会话里打开的扩展页面（以及内容脚本）发的原生消息只交给**这个会话**的 MessageDelegate，没设就一直挂着不回；回复不能是 JSONObject（报 “Invalid event data for callback”），一律回 JSON 字符串。

### A-6 安卓内置页面：耗时操作全部后台化，页面永远有内容（2026-11-14）

- **起因**：用户真机（安卓 15+，edgetunnel 订阅）反馈点“节点与出口”“指纹与时区”后白屏、无响应或一直转圈。
- **查到并修掉的问题**：
  1. `fp.js` 在真 Gecko 里把画布、音频、`Intl…resolvedOptions()` 改坏了：内容脚本里包出来的函数读页面传来的 `arguments` 会被拒绝（`Permission denied to access property "length"`），用到这些接口的网站直接白屏。以前只在 Chromium 普通页面里测过，测不出来。现在用 `exportFunction` + 显式参数重写，并加了自检页 `fpcheck.html`。
  2. `PUT /api/sub`、`POST /api/nodes/test` 同步等 mihomo 拉订阅 / 测完所有节点，节点多、多数不通时要几十秒，期间页面没有任何反馈。
  3. 节点页在渲染过程中发起 `GET /api/nodes`，失败时又触发重画，形成循环。
  4. 页面脚本出错或接口不回时没有任何兜底，表现就是白屏。
- **做法**：见 `docs/android.md`“界面”一节。节点“自动”改成有粘性：当前节点还通就不换，避免每次测速都换出口 IP。
- **没有确认的**：模拟器里旧版从菜单点进这两页是能打开的（没有复现用户的白屏），所以无法证明上面几条就是用户手机上的全部原因；真机 edgetunnel 订阅对 `clash.meta` UA 返回什么也没验证。为此加了“诊断信息”。
- **顺带**：固定调试签名，后续版本可以覆盖安装。

### A-7 指纹参数改为“消息 + 同步请求”交给内容脚本，废弃按容器注册（2026-11-14）

- **问题（第一版就有，第二版的 CI 自检页抓到）**：`contentScripts.register({cookieStoreId: "firefox-container-mt-<id>"})` 在 GeckoView 里不分实例。
  安卓上 Gecko 把 cookieStoreId 的后缀当数字解析（`ext-toolkit.js` 里 `parseInt`，注释写着 Bug 1643740），`mt-<id>` 得到 NaN，匹配条件退化成“默认容器”；
  而 GeckoView 的会话隔离用的是另一个属性（`geckoViewSessionContextId`），所有标签页的 userContextId 都是 0——于是每份注册的脚本对**所有**标签页生效，谁注册得早谁赢。
  后果：所有实例的网页用的是同一个实例的种子、时区和语言（Cookie 和代理分流不受影响，那两样不靠这个）。
  CI 里的表现：实例 #3（东京）的自检页有一次拿到的是实例 #2 的参数（时区 UTC、语言 en-US）。
- **做法**：`fp-boot.js` 在 `document_start` 发消息 `{t:'fp:who', n}`（消息自带来源标签页，后台按标签页认实例，和代理分流用的是同一张表），
  紧接着发同步请求 `https://fp.masktab.invalid/<扩展内部编号>/<n>`；后台 `webRequest.onBeforeRequest` 把两者对上，跳转到 `fpcfg.json?c=<参数>`，内容脚本读跳转后的地址。
  请求不出网（域名不存在，且在发出前就被跳转）。网页不知道扩展内部编号，自己发这个请求只会被取消。
- **为什么不只用请求**：内容脚本发的请求在 webRequest 里 `tabId` 是 -1，认不出标签页（沙箱桌面火狐实测）。
- **代价**：每个页面 / 框架多一次同步往返（桌面实测 10–40 毫秒）；消息 400 毫秒没到就放弃，退回异步。
- **证据**：沙箱真火狐 160 + 整个内置扩展，两个实例交替开自检页各拿各的参数；CI 模拟器结果见 PROGRESS。真机没验证。

### A-5 安卓版的构建方式

### A-8 内置页面不再开对话框：一个 GeckoView、一个常驻页面会话，换路由显示（2026-11-14，第三版）

- **问题**：第二版（0.1.9）发给用户后，真机上点头像能出菜单，但从菜单点“账号与密码 / 节点与出口 / 指纹与时区 / 新建实例 / 导入邮箱 / 管理实例”任何一项都白屏或闪退，还经常卡死。
  CI 模拟器里同样的真点击全过——**模拟器通过不能说明真机没问题**（第二版犯的就是这个错）。
- **真机上的原因没有确认**（拿不到手机日志）。能确定的只有：出问题的每一项都走同一条路——关掉菜单的对话框和它的 GeckoView / 会话，再新建一个对话框 + GeckoView + 会话；
  “新建实例”还是在那个会话自己的消息回调里把它关掉的。也就是每点一下都在销毁、重建绘制表面和内核会话。
- **做法**：不修补这条路，直接去掉它。全应用只有主界面那一个 GeckoView；内置页面用一个常驻会话，显示 / 收起就是 `setSession` 换进换出（与切换标签页相同）；
  页面之间只改路由。于是从菜单点任何一项不再经过任何原生窗口操作，只是同一个页面里换一下 `#`。
- **同时补上取证手段**：原生诊断窗口（见 `docs/android.md`），白屏、卡在启动页时也打得开，带系统记录的进程退出原因。下次再有问题，用户贴这段就能定位，不用再猜。
- **查到并确认的一个卡死**：“导入邮箱”页一打开，GeckoView 的 GPU 进程就卡死，主线程等它等到超时（约 10 秒）后把它杀掉，期间整个模拟器不响应。
  这一页从第一版起就没在模拟器里开过，所以一直没发现。在实验分支上逐项排除（run 43574923756，已删）：怎么打开无关（直接用测试参数打开也卡）；
  去掉弹框的“圆角 + overflow:auto + max-height”就正常，加回来就卡。改成弹框不滚、外面的遮罩滚。真机上是否同样没有确认，但症状（白屏、卡死、闪退）对得上。
- **顺带**：批量导入邮箱时密码库每条都加密落盘（密钥在系统密钥库，每次跨进程）改成一批只落盘一次，免得卡住界面。
- **代价**：菜单从右上角的小弹窗变成整页；地址栏在内置页面显示期间藏起来。
- **仍然没验证**：真机。这一版是“换掉可疑的路 + 能取证”，不是“找到并证明了原因”。

### A-9 手机：人机验证诊断开关（2026-11-13，需求方：两端都过不了 Cloudflare 验证，选了“出诊断开关，逐项试”）

- **背景**：需求方的截图里 Turnstile 报 300030（验证组件在浏览器里执行出错 / 卡死），不是“判定为机器人”。电脑端只重启实例就好了（原因没定，见下）；手机端一直过不去。
  沙箱里测不了（机房 IP + 自动化本身就过不去），真机只有需求方有，所以先做开关让需求方自己定位，不凭猜测改默认值。
- **做法**：设置 → 人机验证诊断（只有手机显示）。11 个开关，每个对应 MaskTab 对内核做的一处改动，默认全开：
  `canvas` 画布噪声、`audio` 音频噪声、`hw` 核心数与屏幕高度、`lang` 语言（网页里和请求头）、`tz` 时区、
  `cfframe` 在 Cloudflare 验证框里也注入、`block` 认不出实例的请求一律拒绝、`ua` UA 里的安卓版本号按种子换、
  `tp` 跟踪保护、`fpp` 内核自带的指纹保护、`sw` 禁用 Service Worker。
  关掉的项记在设置 `fpOff` 里（核心服务只存不解释）；app 存一份在 `host.json`，因为内核偏好要在核心服务起来之前写好。
  生效时机不同（前七项刷新网页、`ua` / `tp` 新开标签页、`fpp` / `sw` 重启 app），页面上统一让用户点“重启 MaskTab”。
- **`block` 关掉时不直连**：认不出实例的网页请求改走“最近一个认得出实例的请求”所属实例的线路。只用于诊断：多个实例同时在用时可能走错实例的线路。
- **顺带记下被拒绝的请求**：内置扩展后台记“认不出实例”的请求（条数 + 最近 20 条的主机名、类型、来源），诊断页上能看，每种还进一次日志（随“复制诊断信息”带出来）。
  怀疑点：网页后台线程（Worker）发的请求在 GeckoView 里可能既没有标签页号、容器号也不准（bug 1948114），于是被拒绝，验证组件就卡死。这是手机独有的、和指纹无关的一条可疑线索。
- **已知的可疑点**（都没验证，等真机结果）：注入脚本改的时区 / 核心数 / 语言在 Worker 里改不到，两边一比就露馅；画布、音频噪声加了两层（内核指纹保护 + 注入脚本）；
  别的浏览器因为这类噪声出现过同样的验证死循环（cromite #2365、helium #249）。
- **电脑端没有改**：上游 fingerprint-chromium #88 报告 148.0.7778.215 在 Windows 上显卡伪装坏了、Cloudflare 验证无限循环，`--disable-spoofing=gpu` 可绕过；
  但需求方没关显卡伪装、只重启实例就能过了，所以不能确定就是它。需求方选了“先不改，再观察”。再出现时先看 `chrome://gpu` 的 Log Messages 里有没有
  `eglCreateContext: Requested version is not supported`，再关“显卡”那一项试。
- **现在的“CF 信誉 / 纯净度”不代表验证能不能过**（UI-3）：前者只是核心服务探得到 CF 那一路的出口；后者来自 ip.net.coffee，需求方的出口它给 0 风险、
  同时自己又检出“住宅代理、VPN 出口”，另一家（ippure）给 88。要改成“在实例自己的浏览器里真跑一次验证”，还没做。

### A-10 手机：网页语言改用内核原生设置，不再在页面里改 navigator.language（2026-11-15，2026-11-16 发布，未真机验证）

- **根因（沙箱复现）**：fp.js 用内容脚本改了主线程的 `navigator.language(s)`，Worker 里改不到（内容脚本进不了 Worker），
  主线程 `ko-KR` / Worker `en-US` 不一致，Cloudflare Turnstile 判 600010。官方火狐 160 + 同款注入，按项二分：只关“语言”就过，
  只改请求头不改 JS 也过，用内核偏好 `intl.accept_languages` 设成 ko-KR（Worker 一起变）也过；JS 改成和真实值相同也过——判的是“不一致”，不是改写本身。
  时区同样改不到 Worker（Worker 里仍是系统时区），这次没被判，但同一类风险。
- **为什么只在开代理时失败**：`expectTZ`（internal/core/proxyflow.go）在代理关掉时不给时区和语言，页面里就不改语言；开代理才按出口给 ko-KR。
- **为什么“诊断全关”也不过**：后台 `fpCfg` 走同步通道时漏了 `off`，fp.js 收不到关掉的项（异步通道带了，但同步先到、`__mtfpDone` 挡住了后来的）。已补上。
- **做法**：`Core.applyLocale()` 按当前实例调 `GeckoRuntimeSettings.setLocales`（内核原生，navigator / Worker / 请求头 / Intl 一起变）；
  fp.js 的语言改写默认关（`cfg.langJs` 才开）；后台不再改 Accept-Language。
  实例语言 ja-JP 时传 `[ja-JP, ja]`；回到系统语言时**显式传系统语言列表，不传 null**：GeckoView 160 的 `GeckoViewStartup` 收到 null 只重算 `intl.accept_languages`，
  不改 `Services.locale.requestedLocales`，Intl 默认语言会停在上一个实例上。安卓 FPP 默认项不含 JSLocale，不会把语言盖回 en-US。
- **代价**：GeckoRuntime 只有一份，后台实例的标签页也跟着当前实例的语言；GeckoView 会把系统语言追加在 `navigator.languages` 后面（computeAcceptLanguages）。
- **回退**：恢复 fp.js 语言段的条件、后台的 Accept-Language 监听，去掉 `applyLocale()` 调用。

### A-11 手机：运行中不再热换时区 / 语言；edgetunnel 不按 Workers 出口定时区（2026-11-16，随 v0.1.51 发布，未真机验证；后续见 A-12）

- **现象（真机 v0.1.50，edgetunnel + ProxyIP）**：CF 网站出口一直是 ProxyIP 210.138.37.53（日本），“普通网站”出口是 Workers 的 104.28.x（Cloudflare WARP 段），
  一会儿韩国一会儿日本。韩国时 Turnstile 过；变成日本后一直 300010，**彻底重启 app 才过**。
- **推断**：实例的时区跟的是“普通网站”那一路（启动日志时区 Asia/Seoul 只能来自 104.28.164.13），Workers 换机房 → 核心服务热换时区和语言 →
  手机上热换后某种只在进程内的状态和新值混在一起。沙箱（官方火狐 160 + 同款注入 + 韩/日语言包）实测：热换后新开 / 刷新的网页里，主线程和 Worker 的
  navigator.language、Intl 默认语言都正确更新，热换前后 Turnstile 都 PASS——所以**残留的不是网页能看到的语言 / 时区值**，而是会话级状态
  （会话 Cookie、TLS 会话、指纹保护的会话随机数、没刷新的网页里注入的旧时区）或核心服务 / mihomo 的状态。哪一样没定，等真机二分（work/turnstile-diag/REPORT-300010.md）。
- **做法**：宿主模式下实例运行中出口时区 / 语言变了，不再热换：网页继续用启动时的值（`LaunchedTZ` / `LaunchedLang`），标“需重启”，不断流；
  手机上“立即重启”重启整个 app（`/ui/restart`），因为 GeckoRuntime 一个进程只能建一次、内容进程没有接口单独重启。
  `expectTZ` 跟“普通网站”那一路时，如果那一路归属是 Cloudflare（WARP / Workers 出口）且有 CF 那一路，改用 CF 那一路。
- **代价**：手机上运行中改固定时区 / 语言、开关代理，也要重启 app 才生效。
- **回退**：恢复 `refreshTry` 里 `Caps().Live` 那一支的热换、`State` 里按 Launched 值给的分支。

### A-12 切换节点不改时区、不要求重启：时区按 ProxyIP 那一路、国家没变就沿用启动时的值（2026-11-16，v0.1.51，接着 A-11，未真机验证）

- **需求方**：只换入口时，时区不能变，也不应该要求重启；只有出口国家真的变了才提示需重启（不强制）；能做到切换节点不用重启更好。
- **做法**（`internal/core/proxyflow.go`）：
  - 定时区的那一路抽成 `tzSrc`：默认 CF 那一路（edgetunnel 下就是 ProxyIP）；设成“跟普通网站”时，那一路如果是 Cloudflare 自己的出站（Workers / WARP）且有 CF 那一路，仍用 CF 那一路（A-11）。只换入口不改 ProxyIP，所以不改这里的结果。`checks.go` 的“时区一致”也改用同一个函数（以前它没跟上 A-11 的规则）。
  - 实例启动时记下定时区那一路的国家和时区（`Runtime.launchedSrc`，不落盘、不进状态）。之后探到的出口**国家没变**就沿用启动时的时区（`expectTZPinned`）：同一个国家里换 ProxyIP（IP 库给了别的时区，例如美国东西海岸）不算变化，不标“需重启”。语言本来就按国家定，国家不变语言不变。
  - 这次没探到能定时区的那一路（两路都没有，或只探到 WARP 那一路）：判断不了，不算变化，放行，不标“需重启”。
  - 国家真的变了：手机上标“需重启”、**不断流**（A-11）；电脑上仍按 F-ISO-4 断流等重启（电脑内核的时区是启动参数，运行中改不了）。
  - 判定逻辑抽成纯函数 `judgeExit`，单测 `TestJudgeExitHotSwitch` 覆盖：Workers 出口变日本 / 香港（只换入口）、同国换 ProxyIP、只探到 WARP、出口换到美国、电脑同国换出口。
  - 换线路时 mihomo 上这个实例的旧连接本来就会关掉（`refreshTry` 里 `CloseConnections`），这次没改。
- **没做：自动清掉该实例 Cloudflare 的 Cookie（cf_clearance、__cf_bm）**。原因：
  - GeckoView 160 的 `StorageController` 只有“清整个容器”（`clearDataForSessionContext`，连登录一起清）和“按域名清全部容器”（`clearDataFromBaseDomain` / `clearDataFromHost`），没有“某个容器的某个 Cookie”。
  - 走内置扩展的 `browser.cookies`：它按 `storeId`（userContextId）、`firstPartyDomain`、`partitionKey` 过滤，而 GeckoView 的实例隔离用的是 `geckoViewSessionContextId`，不在过滤条件里——删的时候分不清是哪个实例的，可能删到别的实例；两个 Cookie 都是 HttpOnly，网页脚本也删不了。
  - 这两条都没法在沙箱里验证（没有 GeckoView）。按需求方“只做低风险、能验证的”，不做。真要做，要么等真机二分确认残留确实在这两个 Cookie 上，再试 `browser.cookies.getAll` 看返回的 `originAttributes` 带不带 `geckoViewSessionContextId`；要么让用户在三点菜单里手动“删除浏览数据”（会清登录）。
- **代价**：同一个国家里换出口时，网页的时区可能和 IP 库给的城市时区差几个小时（只在多时区国家）；“时区与出口所在地一致”那项检查会如实显示不一致。
- **回退**：`judgeExit` 里去掉 `unknown` 那一支，`expectTZPinned` 的 pin 传 nil。

### A-13 启动提速：网络检测先用上次的出口，其余放后台（2026-11-16，v0.1.51，真机未验证）

- **需求方**：手机启动页“加载订阅”“网络检测”很慢。要求启动只做必要的、并行、加超时；用缓存的订阅和上次的出口先进浏览器，其余后台补完；纯净度、CF 信誉不挡启动。
- **慢在哪（读代码 + 沙箱实测）**：
  - **订阅**：启动时**不下载**订阅（宿主模式只读核心服务存着的，代码里也没有定时刷新），这一步只有 app 自己加的 450 ms 停顿。看起来慢，是因为它前面的“启动核心服务”要等内置扩展装好才开始（模拟器上扩展要 6–12 秒），而它自己那一行在等待时不转圈。
  - **网络检测**（`Launch`）串着做：自动选线先现测一次延迟（每次最多 5 秒，最多两次）→ 两路出口探测（两个 trace 并行，12 秒超时）→ 两路归属**先后**各查一次（每个查询服务最多 12 秒，依次 ipinfo.io → ipwho.is → ip-api.com；结果只缓存在内存里，app 每次重开核心服务都是新进程，等于没有缓存）。
  - **实例就绪后又整套重来一遍**（`go a.refresh(id)`）：再选线、再测延迟、再探测、再查归属，而且这一遍期间主通道是 REJECT（`正在确认出口`）——启动页已经收起，刚恢复的标签页打不开。这是“慢”的大头。
  - 纯净度（`ipqEnsure`）本来就在后台；CF 信誉是从探测结果推出来的，不单独查。都不挡启动，这次没改。
- **做法**：
  - 手机：实例的线路（订阅 + 节点；edgetunnel 是订阅 + ProxyIP，入口不算）和上次一样、上次探到过能定时区的出口（3 天内）：**直接用上次的出口**定时区、语言，马上放行；后台 `verifyLaunch` 再探一次（**不断流**）：探到了按 A-12 判定（国家变了提示需重启），这次不通或只探到一路才走完整流程（断流、自动换线）。上次的出口存在 `state/lastexit.json`（实例 id → 线路、探测结果、时间）。
  - 归属查询结果落盘（`state/ipinfo.json`，7 天，最多 300 条），新进程读回来就不用再查；两路归属并行查；查询服务单个最多等 6 秒就换下一个。
  - 实例就绪后不再整套重来：启动时刚探过的，只 `afterLaunch`（放行 + 后台补测延迟、纯净度）。电脑版同样（启动后不再断流重探）。
  - `refreshTry` 里测延迟和出口探测改成并行。
  - app（`MainActivity.boot`）：核心服务和内置扩展同时开始启动，不再等扩展装好；去掉每步至少 450 ms 的停顿；最后一步的停留从 500 ms 改成 250 ms；每步日志带上距启动的毫秒数。
- **前后对比（沙箱实测，宿主模式核心服务 + 真 mihomo + ss 测试节点，节点前面加了每个方向 120 ms 的延迟，模拟手机到节点约 240 ms 往返；从核心服务就绪、开始启动实例算起）**：
  - 旧版（0.1.50）：实例就绪 3.1–3.3 秒，**网页能开 6.6–6.7 秒**（就绪后又断流重探约 3.4 秒）。
  - 新版，线路和上次一样（重开 app 的常见情况）：就绪、网页能开都是 **0.06 秒**；后台确认出口 1.2 秒后补上延迟。
  - 新版，没有上次的出口（第一次、换了线路）：就绪即能开网页 **3.2 秒**，延迟 4.4 秒时补上。
  - 另外 app 侧省掉：三步各 450 ms 的停顿；核心服务不再排在内置扩展之后（模拟器日志里扩展 6.5–12 秒、核心服务 1.2–1.9 秒，可以重叠）。真机上的绝对时间取决于网络，没测。
- **代价 / 风险**：
  - 上次的出口这次如果换了国家：网页先用旧时区开起来，一两秒后后台确认，提示需重启（A-11 / A-12，不断流）。
  - 上次的节点这次不通：先放行（mihomo 那边连不上，网页报错，不会直连，R-1 不破），后台确认失败后走完整流程断流、换线。
  - 启动后不再立即重探：探测和就绪之间出口如果刚好变了，要等下一次换线或手动“探测”才发现。
- **回退**：`Launch` 里不取 `cachedExitLocked`（`cached` 恒为 nil）、就绪后改回 `go a.refresh(id)`；app 的 `boot()` 恢复串行。

### UI-1 两端全部界面换成 Chrome 风格，一套组件

### UI-2 手机上浮在网页上的三样原生画

- **结论**：头像菜单（底部弹出）、三点菜单（新版 Chrome 的排法）、标签页切换器（顶栏下一排实例头像 + 两列卡片）由 app 原生画（`MainActivity.kt` / `Chrome.kt`）。其余页面仍是共用的扩展页面。

- **怎么守住 D-4**：浮层里的数据全部来自核心服务的状态（`Host.kt` 只是多读了几项：延迟、账号数、一致性检查、纯净度、CF 信誉），点下去要么调核心服务的接口（新建实例、书签存进 `settings.bookmarks`），要么打开内置页面的路由。没有在 Kotlin 里实现业务。

- **和设计稿不一样的**：三点菜单里“无痕式标签页”“添加到新标签页组”“下载内容”画成灰色（点了说明原因）：每个实例本来就是独立容器、标签页组和下载都还没做。

### UI-3 伪装度、纯净度、CF 信誉怎么算

- **伪装度** = 核心服务算的一致性检查（`internal/core/checks.go`，`/api/state` 里每个实例的 `checks`）通过的比例：经代理、出口可用、时区与出口一致、语言与出口国家一致、两路出口同国、CF 网站可达、出口纯净度 ≥ 50、设置已生效、UA 与内核一致、WebRTC 只走代理。
  出口还没探出来时判断不了的项不计入分母（显示“判断不了”），免得刚启动时显示一个吓人的低分。
- **纯净度** = 核心服务查好的出口 IP 纯净度（`st.ipq`，来源 ip.net.coffee，设置里可关）；查不到就画灰色空环，不编数字。
- **CF 信誉** = CF 网站那一路探不探得到出口：探到 = 良好；只有普通网站那一路 = 不可达；其余 = 未知。
- 两路出口在不同国家时，新标签页卡片和节点页出口卡片上给黄色提示。

### UI-4 手机全面屏与状态栏 / 导航栏颜色

- **现象**：用户反映顶部和底部的颜色有时对不上。原因：以前整列内容按 systemBars + ime 留内边距，状态栏、导航栏的底色交给系统（主题里写死白色）；
  安卓 15 起强制全屏绘制，系统不再给两条栏涂色，露出来的是窗口背景，和页面（深色 / 浅色、是否盖着对话框）对不上。
- **做法**：
  - 全面屏：`setDecorFitsSystemWindows(false)`（11+）/ `LAYOUT_FULLSCREEN | LAYOUT_HIDE_NAVIGATION`（8–10），两条栏透明、关掉系统的对比度遮罩，刘海用 `LAYOUT_IN_DISPLAY_CUTOUT_MODE_ALWAYS / SHORT_EDGES`。
  - 根布局 `BarsLayout` 按 insets（状态栏 + 刘海、导航栏 / 手势条、键盘）给内容留边，自己把露出来的那一圈涂成当前页面的颜色：网页和新标签页 = 工具栏底色；内置页面 = 页面底色；
    页面里盖了遮罩（对话框）或底部表单时，页面经 `POST /ui/bars {src, dim, sheet}` 告诉 app，app 把两条栏一起压暗 / 涂成表单底色。
  - 图标深浅：按两条栏各自的底色算亮度，亮底用深色图标（`APPEARANCE_LIGHT_STATUS_BARS / NAVIGATION_BARS`，10 及以下用旧标志位）。
  - 原生浮层盖住整个窗口（连两条栏），遮罩压暗时两条栏跟着变暗；底部弹出的头像菜单一直铺到手势条底下。
  - 键盘：内容底边 = max(导航栏, 键盘)。
- **证据**：只有 CI 模拟器（API 35）截图；刘海屏、三键导航、横屏、安卓 8–10 都没有在真机上看过。

### UI-5 下拉刷新

- **结论**：和官方 Chrome 一样：网页滚到最顶、往下拉，顶上出现圆形指示器，拉过 80dp 松手刷新，加载完收起（最多转 8 秒）。只在显示网页时生效（内置页面、新标签页不触发）。
- **做法**：`PullRefresh`（FrameLayout，包着 GeckoView）拦截手势的条件是三个同时成立：
  ① 页面在顶部（`GeckoSession.ScrollDelegate` 报的 scrollY = 0）；
  ② Gecko（APZ）对这次按下的判断：没被网页自己接手（不是 `INPUT_RESULT_HANDLED_CONTENT`：preventDefault、里层可滚动区域）、页面不能再往上滚（没有 `SCROLLABLE_FLAG_TOP`）、允许纵向越界（CSS `overscroll-behavior` 没关）——`GeckoView.onTouchEventForDetailResult` 给的 `InputResultDetail`，和 Fenix 的做法一样；
  ③ 手指明显向下（超过 touch slop，纵向是横向的 1.5 倍）。拦截后网页收到 CANCEL，之后由指示器接手。没用 SwipeRefreshLayout：项目不依赖 AndroidX（A-5）。
- **证据**：CI 模拟器冒烟里在 example.com 顶部往下拉要触发刷新、往上滑不能触发。真机、长页面、网页自己有下拉手势的站点没有测。

### UI-6 Windows 任务栏图标（A 方案：浏览器图标右下角加彩色编号角标）没有做

- **结论**：没做，留作后续。
- **原因**：
  - 任务栏上的窗口属于内核进程（fingerprint-chromium 的 chrome.exe），不属于核心服务。给它加角标要调 `ITaskbarList3::SetOverlayIcon(窗口句柄, 图标)`；这个接口按文档只对调用者自己进程的窗口可靠，跨进程给别人的窗口设角标不保证生效。
  - 另一条路是改窗口属性（`SHGetPropertyStoreForWindow` 写 `PKEY_AppUserModel_RelaunchIconResource` / 改 AppUserModelID）：Chromium 自己会按用户目录设置 AppUserModelID 并在窗口创建时写这些属性，外面改了会被覆盖，也会打乱任务栏分组。
  - 现有代码里没有任何任务栏 / AppUserModel / .ico 的实现可以接着做；没有真实 Windows 桌面验证（CI 的 Windows Server 截图看不出任务栏角标是否稳定）。
- **影响**：任务栏上各实例仍是同一个浏览器图标，要靠窗口里的工具栏头像（M-2）区分。要做的话，比较稳的办法是改内核（在 Chromium 里按 `--fingerprint` 种子 / 实例编号画角标），不是在核心服务里做。

### UI-7 弹框不滚，遮罩滚（“圆角 + overflow 滚动”在模拟器里卡死 GPU，第二次踩到）

- **现象**：分支 `ui/chrome` 第一次推送（7901253）的模拟器冒烟（Android run 43622971231）里，打开“导入邮箱”后 GeckoView 的 GPU 进程卡死被杀（logcat：`Killing GPU process due to IPC reply timeout`），之后每张截图都截不出来，整个脚本超时。
- **原因**：重写 `ui.css`（UI-1）时，`.dlg`、`.modal`、`.sheet` 又写成了“圆角 + `overflow-y:auto` + `max-height`”。这正是 A-8 里用 run 43574923756 逐项排除定位到的组合，旧 `android/ext/app.css` 里写着这条规矩，但重写时这条注释没有跟过来。
- **做法**：遮罩 `.scrim` 自己滚（`overflow-y:auto`，纵向 flex），弹框不滚也不限高：`.dlg` / `.modal` 用 `margin:auto` 居中（比屏幕高时 auto 归零、从顶上排，遮罩滚）；`.sheet` 用 `margin-top:auto` 贴底（电脑上 `margin:auto` 居中）。规矩写回 `ui.css` 的注释。
  全仓库搜过：别的可滚动容器（`.chips`、`.accs`、`.drawer`、`.pnav`、电脑弹窗的 `.insts`）都没有圆角；输入框 / 文本框不算（以前实测不受影响）。
- **防止第三次**：`preview-pages.mjs` 新增检查：每个预览页面和打开的对话框里不能有“圆角 + overflow:auto/scroll”的元素；矮屏（412×420）上的导入邮箱弹框必须是遮罩滚、弹框本身不滚不截断。用旧的 `ui.css` 跑，这两项都会失败。
- **同一次 run 里的另两处失败**（不是界面问题，是测试找错了控件 / 参数被吃掉）：
  - 新标签页的伪装概况卡 `aria-label` 写成了“节点与出口”，和原生头像菜单的项重名；冒烟按无障碍标签找控件时先找到网页里的那个，点的坐标落在菜单的空白处，于是“从头像菜单点开 node”“反复开关 12 轮后”两项失败。卡片改叫“伪装概况”，`preview-pages.mjs` 加检查：新标签页的无障碍标签不能以原生菜单项的名字开头。
  - `emulator-smoke.sh` 里 `adb shell am start ... --es mt_inst '#1'`：adb 把参数拼成一行交给设备上的 shell，`#1` 被当成注释，`am` 报 `Argument expected after "mt_inst"`，没有切回实例 #1。改成整条命令作为一个字符串传。
- **下拉刷新（补充 UI-5）**：这次 run 在下拉刷新那一步之前就超时了，所以这项在模拟器上还没真正跑过。顺带放宽了一个条件：Gecko 报“没人接手”（`INPUT_RESULT_UNHANDLED`，整页不能滚的短页面，例如冒烟用的 example.com）时直接算可以下拉，不再要求越界方向里有纵向——这种情况下 Gecko 给的越界方向不一定可靠，按原条件短页面可能永远拉不出刷新。

### UI-8 左右不被遮挡：启动页按左右 insets 留边，页面处理左右安全区（2026-11-16，v0.1.51）

- **现象（用户截图，vivo V2419A，Android 17）**：启动页左边的绿色勾被裁掉一半，右边“mihomo v1.19.3…”被截断。
- **原因**：不是 edge-to-edge 的 insets，是启动页的宽度算错：每一行固定 `min(320dp, 屏宽 - 48dp)`，而列两边各留 32dp。屏幕窄于 384dp 时（把“显示大小”调大的手机，这台约 360dp），行比列宽 16dp，被列的内边距裁掉（`clipToPadding`）。截图里裁掉的位置正好是 32dp。
  另外启动页以前只拿了上下 insets，没拿左右的（横屏刘海、三键导航时会被挡）。
- **做法**：
  - 启动页（`StartupView`）：行宽跟着列走（`match_parent`），列的左右留边 = 左右 insets + max(24dp, 居中留白)，内容最宽 320dp；屏幕尺寸变了重新算。
  - 三点菜单的宽度扣掉左右 insets。其余原生浮层本来就按左右 insets 留边（`fitOverlay`），网页 / 内置页面所在的那一列也一直按左右 insets 留边（UI-4）。
  - 内置页面：`viewport-fit=cover`；`ui.css` 里 `body`、全屏遮罩、抽屉按 `env(safe-area-inset-left/right)` 留边，悬浮按钮、提示条跟着让开。手机上 app 已经把网页区域让开了，`env()` 一般是 0；电脑上恒为 0。
  - 顺带修了一处真的横向溢出：实例管理（手机精简版卡片）在 320 / 360 宽时卡片撑出屏幕右边 50px，最右边的开关按钮被挡住（`grid-template-columns: 1fr` 的下限是卡片的最小内容宽度）。改成 `minmax(0, 1fr)`。
- **防再犯**：`preview-pages.mjs` 新增两项：320 / 360 宽下每一页不能横向溢出、不能有元素伸出屏幕左右边；模拟左右各 40px 的安全区，节点页内容要让开。
- **没验证**：启动页的改动是 Kotlin，沙箱编译不了，靠 CI 构建和模拟器截图；真机（vivo 那台）没看过。网页（网站）本身的左右安全区由网站自己决定，app 这边是整列让开。

### UI-9 选中用底色、少数几项用下拉栏、有图标不写字、同一件事只出现一次（2026-11-13 需求方定，演示第 3 ~ 5 轮）

需求方看过五轮演示（`masktab-原生界面demo.html`）后定下的四条，适用于全部界面：

1. **选中 = 整行 / 整张卡片换底色**（`--tonal` / `--ontonal`）。行尾不放单选圈，不写“当前”“使用中”“运行中”这类标签。`.radio` 已从 `ui.css` 删掉，不要再加回来。
2. **从少数几项里选一个用下拉栏**（`ui.js` 的 `dropdown(anchor, opts, cur)`），从点的那一行 / 那个按钮长出来，不换页、不弹对话框。国家（出口国家、入口国家、列表的国家筛选）、排序、设置里的单选项都是它。
   `choose()` 保留原来的签名：找得到“刚按下的那一行”就开下拉栏，找不到（脚本直接调用、连着第二次选择）才退回对话框，对话框里同样用底色表示选中。
   下拉的那一行右边画“∨”（`row({ drop: true })`），进下一页的才画“>”。
   下拉栏的盒子有圆角，所以自己不滚（UI-7）；比屏幕长时滚的是外面那层透明遮罩。遮罩是 `.scrim.dd`：手机外壳的系统返回键照样先关它，但不压暗状态栏。
3. **有图标就不再写字**：住宅 / 机房 / 手机流量只画图标（悬停、读屏有字）；国旗后面不再写国名（下拉栏的选项里才写）；“普通网站”一律写成“普网”。
4. **写全、不重复**：IP 不截断（IPv6 换小字号、允许折行，不用“…”）；同一件事一页只出现一次。

节点与出口首页据此重排（`panel.js`）：

- 出口卡片一张说完当前出口：哪类网站（“CF 网站” / “普网” / “全部网站”）、国旗 + 完整 IP（点一下复制）、类型图标、城市 · 运营商、CF 信誉、延迟、纯净度；两路不同时第二行列另一路；不在同一国家时提示里带“改自动”。
- “自动选择”是模式开关。**开**：下面只有“出口国家”一行（下拉栏），“换一个”放在分组标题右边。**关**：换成“从列表里选”和“自定义 ProxyIP”两行，正在用的那一行换底色并写出用的是哪个。“当前出口 / 当前入口 / 当前节点”三行删掉了。
- 入口同理：开 = 现在用的入口写在开关的副标题里，下面是“入口国家”（下拉栏，默认“跟随出口”）；关 = “从列表里选”“自定义入口地址”。
- “出口国家”那一整页删掉了（视图 `region` 没有了）。

**入口国家是新功能**（`InstProxy.EntryRegion`，接口字段 `proxy.entryRegion`）：入口自动时先在这个国家里挑入口。只在两种情况下听它的（`pick.go` 的 `entryWant`，有单元测试）：反代已经定下来，或者出口没限国家。
出口限了国家、又没有反代可用时，CF 网站也是从入口所在国出去的，入口换国家等于出口换国家，和“出口国家”打架，所以不听。指定的国家里没有能用的入口 → 按“跟随出口”的老办法挑，并提示“<国家>没有可用的入口，已跟随出口”（`noentry:` 代号）。
要知道的后果：edgetunnel 上普通网站的出口由入口所在的机房决定，所以入口国家和出口国家选得不一样时，出口卡片会提示“两路出口不在同一国家”。这是这个选项本来的意思，不拦。

**自定义 ProxyIP / 自定义入口地址**：填一个 → 走原有的 `POST /api/exits` 加进地址库 → 立刻选中（手动）。域名要先解析、探测，那种情况只加进地址库并提示“探测完后在列表里选”。
演示里的“加进地址库”开关没有做：核心服务里出口只能引用地址库里的条目，“不进库的一次性地址”要另加一套存储，等需求方明说要再做。

**这次没有移植的**（演示里有，都是手机原生 Kotlin 画的，沙箱编译不了、只能靠 CI 模拟器截图）：工具栏按钮顺序、地址栏聚焦动画、扩展面板、原生头像面板和三点菜单的新排法、“收纳袋”标签页切换动画；以及“每行一个圆角色块”的整体换肤、头像面板上的实时流量、实例卡片分“运行中 / 休眠”两组。

检查：`preview-pages.mjs` 新增 / 改写 14 项（下拉栏的项数、选中项换底色、不伸出屏幕、页面上没有 `.radio`、自动 / 手动两种排法、列表里 IP 没被截断、两端下拉栏内容一致、系统返回键先关下拉栏）。

### UI-10 页面的样子照定稿的演示（2026-11-16 需求方定：“你没有按照 masktab-原生界面demo.html 的 ui 来深化”）

UI-9 只把演示背后的四条规则套到了旧页面上，页面本身还是旧样子，需求方不认。这一条把演示的**外观**搬进源码，两端一起：

1. **颜色跟着当前实例走。** 强调色、选中底色、各层卡片的底色都由实例色的色相 / 饱和度算出来（`ui.js` 的 `accentTokens`，手机外壳 `Chrome.kt` 的 `Theme.of`，同一组公式，改一边要改另一边）。页面底色 `--bg` 不变，外壳涂的状态栏 / 导航栏照旧对得上。
2. **每项自己一块。** 设置行、勾选行、菜单项各是一块，块之间留 2px 的缝，一组的头尾是 20px（电脑 16px）大圆角；小标题是灰色小字。不加包裹元素，靠相邻兄弟选择器和 `:has()`。
3. **头像菜单**：当前实例是一张实例色的卡片（名字、国旗 + 完整 IP + 延迟、实时流量、网站图标、纯净度圆环）；四项入口各一块；“其它实例”标题右边只有“新建实例”，下面每个实例一块，运行中的用它自己的颜色做底、休眠的变淡。手机上“管理实例”“导入邮箱”不在这里了：管理在 三点菜单 → 设置 → 实例，导入在实例页右上角。电脑弹窗是唯一的入口，标题右边留着图标按钮（管理、导入、设置、关闭这个实例）。
4. **实例页**分“运行中 / 休眠”两组，卡片 = 头像、名字、一行出口（国旗 + IP + 延迟 + 账号数）、网站图标；当前实例换底色加描边；休眠的右边是启动按钮。拖动排序只在同一组里。
5. **新标签页**：搜索框、实例卡（实例色）、伪装概况三格（伪装度、纯净度、CF 信誉）、书签、最近访问。
6. **手机工具栏**（原生）：头像在最左，地址栏，扩展，标签页数，三点。原来的“主页”按钮去掉（三点菜单里有“打开新的标签页”）。
7. **三点菜单**（原生）只留浏览器自己的项：新标签页、历史记录、删除浏览数据、下载内容、书签、最近打开的标签页、更多工具、设置、帮助和反馈。节点、指纹、实例在头像菜单里，扩展在工具栏上，不重复。“更多工具”演示里没有，留着是因为诊断信息、分享这些功能没有别的入口。
8. **标签页切换器**（原生）：左上角“+”，标题“标签页”，一排实例，两列卡片；选中的卡片用选中底色。

**没有做的**（演示里有）：地址栏聚焦页（最近访问 + 书签）、从工具栏弹出的扩展面板（现在点扩展图标直接进扩展页）、“记住这个登录？”底部卡片的新样子、原生头像菜单里的实时流量和网站图标（外壳拿不到这两项数据，要先在核心服务的状态里加字段）。

### UI-11 外观默认跟随系统；电脑弹窗照浏览器自己的菜单配色（2026-11-16 需求方截图：浅色的浏览器里弹窗是深色的、“颜色不原生、没有圆角”）

1. **“外观”默认 = 跟随系统**（以前默认深色）。没设过的（`settings.theme` 为空）两端都跟着浏览器 / 系统的深浅色；设过“深色”“浅色”的不变。涉及：`ui.js` `applyTheme`、各外壳传的默认值、`pages.js` 的选项顺序、手机 `Host.theme` / `Theme.isDark`、窗口初始底色（`values` 白、`values-night` 深）。
2. **电脑工具栏弹窗的配色**：整块用带实例色调的浮层底色，里面每一块比它亮一层（浅色下是白的），再弹出来的下拉 / 对话框又亮一层；首页、节点页、指纹页在弹窗里换的时候底色是同一个。做法：`popup.html` 的 `<html class="popup">`，`applyTheme` 见到它就把 `--bg / --surf2 / --surf` 换一组。
3. **弹窗首页不整体滚动**：上半截固定，只有“其它实例”一段在剩下的高度里滚（以前弹窗右边一条滚动条、列表里又一条）。滚动条改细、没有底槽。
4. **弹窗外框的圆角改不了**：外框（那一圈边和四个角）是浏览器画的，扩展只能画框里面的网页，也不能把网页做成透明的让角露出来。浏览器自己的“扩展程序”菜单有圆角是因为它整个是浏览器画的。所以这里做的是让框里的底色和浏览器菜单是一路的，方角不扎眼；要圆角只能换内核 / 系统（内核画弹窗时带圆角的版本、或系统给窗口加圆角）。

检查：`preview-pages.mjs` 加 4 项（没设外观时弹窗跟着浏览器的浅色 / 深色；实例多时弹窗整体不滚；浅色下底色带色调、每块是白的）。`emulator-smoke.sh` 加一段把系统切成深色再截图（模拟器默认浅色，所以原生部件的浅色、深色各有截图）。
