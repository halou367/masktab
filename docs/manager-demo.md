# 实例管理改版：演示稿与实现计划（2026-11-14）

演示页：`demo/manager/manager.html`（双击打开，不需要核心服务；数据存浏览器 localStorage，可随便点）。
源文件是 `manager.src.html`，改完跑 `python3 demo/manager/build.py` 把国旗内嵌进去。

## 需求（来自需求方，2026-11-14）

1. 启动 / 重启时有进度动画：组件检查、代理内核、网络连通检测等。
2. 浏览器**绝对不受**本机 TUN 或系统代理影响。
3. 实例管理里看到每个实例记住的账号（Cookie、账号密码）；网站不支持记住密码时由 MaskTab 记住，掉线 / 退出后自动填写。
4. 卡片上用网站图标（Google、GitHub、Vorflux……）表示这个实例记住了哪些站，一眼看出每个号记住了什么。
5. 卡片只显示国旗，鼠标移上去才显示 IP 详情。
6. 长按卡片拖动排序。
7. 导入邮箱：设一个默认密码，粘贴 N 个邮箱（可带各自密码）→ 自动建 N 个实例，以邮箱命名；登录时用这个密码自动填；
   在该实例注册新网站时提醒用默认密码。一个邮箱一个实例，相互隔离。

## 已落地的部分：不受 TUN / 系统代理影响（需求 2）

- 浏览器内核本来就只认 `--proxy-server`（本地 mihomo）和 `--host-resolver-rules`，系统代理、环境变量对它无效。
- 漏洞在 mihomo 往外连时走系统路由表：本机开了 Clash / sing-box 的 TUN，默认路由指向 TUN，流量被二次代理，DNS 也可能被 fake-ip 劫持。
- 现在：`internal/netx/physif.go` 识别物理网卡（开着、有 MAC、名字不像虚拟网卡、地址不在 198.18.0.0/15 等 TUN 段，优先私网地址），
  - mihomo 配置写 `interface-name: <网卡>`（Windows 上是 IP_UNICAST_IF，不看路由表），DNS 改用 223.5.5.5 / 119.29.29.29 / DoH（按 IP），不用系统 DNS；
  - 核心服务自己的直连请求（edgetunnel 直接探测、ip-api、纯净度查询）用 `netx.BindDialer` 绑定同一块网卡；
  - 设置里新增“不受本机 TUN / 系统代理影响”：自动（默认）/ 关；`/api/state` 的 `net` 字段给出绑定的网卡和发现的 TUN 网卡。
- **没在 Windows 上验证**：需要在开着 Clash Verge / v2rayN 的 TUN 模式时，确认实例出口 IP 不变、延迟不变。单元测试只覆盖了网卡挑选和配置生成。
- 下载组件（首次运行）仍按原设计：直连 → 本机代理 → 镜像，不绑定网卡。

## 待实现（按建议顺序）

1. **排序与卡片**：`Instance` 加 `order` 字段；`PATCH /api/instances/order {ids:[…]}`；管理页按演示改为卡片网格。小改动，可以先做。
2. **启动进度**：核心服务启动时已有 `setup` 状态（下载进度、CoreError）。增加 `setup.steps=[{id,state,detail}]`，
   在 `ensureCore`、`refreshBind`、连通检测（直连 `cp.cloudflare.com/cdn-cgi/trace`，绑定网卡）、订阅刷新、测速、恢复实例各步更新；
   不依赖内核的进度页（`companion/setup/setup.html`，系统浏览器打开）和管理页都读它播放动画。
3. **Cookie 列表**：伴随扩展加 `cookies` 权限，在每个实例里用 `chrome.cookies.getAll({})` 按 eTLD+1 汇总后报给核心服务（只报域名和数量，不报值）；
   导出时才取值。实例休眠时显示上次汇总的结果。
4. **密码管理（计划里的 F-PWD）**：
   - 存储：`data/vault/<实例ID>.json`，每条 `{site, origin, username, password, auto, createdAt, lastUsed}`；密码用 Windows DPAPI（`CryptProtectData`，当前用户范围）加密，
     其它平台用随机主密钥 + AES-GCM，主密钥放系统钥匙串。实例之间文件分开，实例只能经本地接口读到自己的条目（接口按 `X-MaskTab-Inst` 过滤）。
   - 采集：伴随扩展的内容脚本监听登录表单提交（有 `type=password` 的表单），弹出“记住这个账号？”；
     导入邮箱时直接写入邮箱本身那一条。
   - 填写：内容脚本在登录页（有密码框）请求本实例匹配该站点的条目，显示下拉；条目开了“自动”且页面只有一个匹配时直接填并提交（掉线后自动重登）。
   - 注册提醒：页面上有两个密码框、或 URL / 按钮文字含 signup / register / 注册 时，提示“用本实例的邮箱 + 默认密码”，一键填入并记住。
   - 站点图标：优先实例自己的 favicon（`chrome://favicon2` 不可用于扩展页时，由内容脚本上报 `link[rel=icon]`，核心服务缓存成 PNG），常见站点用内置矢量图标。
   - 查看密码前要求验证 Windows 账户（`CredUIPromptForWindowsCredentials`），复制后 30 秒清剪贴板。
5. **导入邮箱**：`POST /api/instances/import {defaultPassword, lines}` → 批量建实例（名 = 邮箱，`mail` 字段记邮箱），并写入密码库；默认密码存进密码库的“全局”条目（同样 DPAPI 加密），不明文落盘。

## 头像即实例（演示：`demo/avatar/avatar.html`，2026-11-14）

需求：节点 / 实例功能不要像“一个插件”，要像浏览器原生的；右上角原来的个人资料头像位置，点开就能看当前实例、切换 / 打开其它实例。

演示内容：工具栏右侧是实例头像（实例色圆 + 首字母 + 国旗角标 + 延迟点，可选带实例名的胶囊样式）；点开是照 Chromium 个人资料菜单版式做的菜单：
当前实例大头像、出口 IP 与延迟、记住的账号图标；密码与自动填写 / 节点与出口 / 指纹与时区；其它实例列表（可搜索，运行中的“切换”= 聚焦它的窗口，休眠的“打开”= 拉起）；新建、导入邮箱、管理、关闭本实例。

### 怎么做到“原生”（实现方案）

原生头像菜单是 Chromium 的 C++ 界面，现成的 fingerprint-chromium 内核**改不了它的菜单内容**；完全替换只能自己编内核打补丁（代价大，且每次升级内核都要重打）。不打补丁的做法：

1. **伴随扩展的工具栏按钮就是头像**：图标用现有的 RGBA 拼图方式（不经画布读回，见 K-3）合成“实例色圆 + 首字母 + 国旗角标”；字母位图预先打包成 RGBA。弹出页就是演示里的菜单（宽 340，扩展弹窗上限 800×600 够用）。
2. **固定在最右、不进拼图菜单**：用策略 `ExtensionSettings` 的 `toolbar_pin: "force_pinned"`（Chromium 的托管策略；Windows 写 `HKCU\Software\Policies\Chromium`，只对本内核生效还要再确认）。【需验证】
3. **原生头像也跟着变**：每个实例是独立的 user-data-dir，启动前写它的 `Local State` 里 `profile.info_cache.Default.name = "#3 carol"`、头像图标与主题色一致，这样原生按钮显示的也是实例名；原生菜单里“添加 / 访客 / 管理个人资料”通过策略 `BrowserAddPersonEnabled=false`、`BrowserGuestModeEnabled=false` 关掉，避免误用。【需验证：148 版内核是否读这些策略、头像按钮能否因此隐藏或只剩名字】
4. **切换**：菜单里点实例 → `POST /api/instances/{id}/launch`；运行中的实例核心服务已有 `focus` 事件把它的窗口拉到前台，休眠的就启动。
5. 快捷键保持：Ctrl+M 新建、Ctrl+Shift+M 管理、Alt+P 打开这个菜单。
